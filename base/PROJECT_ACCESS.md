# Независимые права проектов

В карточках пользователя и группы назначаются отдельные роли:

| Проект | Роли |
| --- | --- |
| Мотивация | Администратор проекта, Генеральный директор, Политик, Продажи, Зам. директора, Директор, Смотрящий, Финансист |
| Модель закупок | Администратор проекта, Логист |
| Дашборды | Администратор проекта, Аналитик |

Общий администратор портала (прежняя роль «Администратор» или superuser)
сохраняет полный доступ ко всем проектам, пользователям, группам и Django admin.
Роль «Администратор» **в отдельном проекте** не делает пользователя общим
администратором и не устанавливает `is_staff`; она даёт управление только
своим проектом. Например, администратор Дашбордов управляет снимками и расписанием,
но не пользователями портала и не Мотивацией.

Порядок разрешения каждого проекта:

1. Общий администратор — полный доступ.
2. Явная персональная роль (включая «Нет доступа») имеет приоритет.
3. При наследовании используются назначения проекта из групп. Пустая роль
   группы не даёт доступ. Разные непустые роли групп закрывают только этот проект;
   персональное назначение разрешает конфликт.
4. Если новых назначений нет, сохраняются прежние права, определяемые общей ролью.

Выбор «Наследовать» удаляет персональную/групповую запись проекта. «Нет доступа»
создаёт явную пустую запись, поэтому не возвращает старый доступ. Старые общие
роли вынесены в блок совместимости. Миграция `base.0005` создаёт только таблицы
`UserProjectAccess` / `GroupProjectAccess`, не переписывая прежние назначения.

Ограничения автора, филиалов, пилотных периодов и утверждённых версий применяются
к роли **проекта Мотивация**. Членство в группе другого проекта не добавляет
подразделения Мотивации. Роль Политик/Директор в Мотивации не запрещает независимый
доступ к Дашбордам или Закупкам. Проверки выполняются middleware и сервисами;
скрытие ссылок не является механизмом защиты.

Сохранение карточки проверяет персональные ФИО/подразделения и группы для
руководителей Мотивации. Для Аналитика и Логиста они не нужны. Сохраняется
защита от снятия собственной общей роли администратора через карточку пользователя.
