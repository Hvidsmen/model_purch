# Пользователи, группы и личные отчёты

После обновления выполните `python manage.py migrate --settings=portal.settings_local` на рабочей базе и перезапустите портал.

## Добавить пользователя

Администратор открывает «Пользователи и права» → Add user / «Добавить пользователя».

- Локальная запись: логин без домена и локальный пароль.
- Доменная запись: `DAICHI\samaccountname`, например `DAICHI\etladmin`. Пароль не заполняется, в AD ничего не создаётся и не меняется. Логин проверяет Windows при входе. Запись портала не имеет локального пароля.
- Логины доменных записей нормализуются в нижний регистр; дубликаты с другим регистром запрещены. Для заранее создаваемой записи нужен фактический samaccountname, а не UPN-псевдоним.
- Укажите роль. После создания открывается карточка пользователя: можно добавить ФИО/почту, изменить роль, назначить дополнительные группы или отключить признак Active.

## Политик

Эта роль открывает только:

1. «Мотивация. Дашборд»;
2. «Мотивация. Детально»;
3. «Факт закрытых сделок».

В карточке обязательны «Подразделение для личных отчётов» и «Точное ФИО автора сделки». После выбора подразделения форма загружает подсказки ФИО из DataWH по типу коэффициента «Политики». Если DWH временно недоступен, администратор может вручную скопировать точное ФИО из отчёта. Автоматического сопоставления только по фамилии нет.

Тип коэффициента закреплён как «Политики». Подразделение и автор сделки закреплены в фильтрах. Сервер применяет эти ограничения независимо от параметров URL, включая выборки для дополнительных столбцов, справочники фильтров, показатели выполнения, Excel и CSV. Доступ к планам, коэффициентам, общему отчёту по подразделениям, закупкам и администрированию запрещён. У пользователя без привязки доступа к отчётам нет. Смена привязки администратором применяется со следующего запроса.

Общие роли «Администратор», «Генеральный директор» и «Логист» сохраняют прежние права. Новая роль не создаётся из названия группы, похожего на роль; действуют только системные имена. Несколько разных системных ролей у одной записи приводят к отказу в доступе, а не объединению прав.

## Группы пользователей

В меню администратора есть «Группы пользователей». Создайте дополнительную группу, задайте её название и выберите участников. Участников можно добавлять и исключать также через карточку пользователя; персональная роль и привязка к отчётам сохраняются.

Группа используется для объединения пользователей и стандартных разрешений Django. Доступ к разделам портала определяется персональной системной ролью, а личные данные — её привязкой. Дополнительная группа не расширяет данные «Политика». Системные группы ролей защищены от удаления и переименования, их состав назначается через поле роли пользователя.

## Проверить права

Используйте «Просмотреть как пользователь». Меню и ограничения будут соответствовать выбранному пользователю; запросы на изменение данных в этом режиме запрещены. Кнопка в баннере возвращает администратора к его правам.
