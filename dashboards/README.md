# Дашборды / Динамика дилерской базы

Третий проект портала: `/dashboards/`. Сейчас доступен только роли
«Администратор» (включая просмотр от её имени по общим правилам портала).
Отдельных таблиц SQLite, миграций, SQL-процедур и фоновых заданий не создаёт.

## Источник

Используется существующее подключение `DWH_SQL_CONN_STR` к DataWH.
`sql/dealer_sales.sql` выполняет только SELECT. Данные агрегируются до месяца,
кода дилера, филиала и товарных разрезов; код передаётся отдельно от названия.

Условия, согласованные с заказчиком:

- `sub.Chanel = N'Дилерский'`;
- семь брендов из исходного запроса;
- `Split`, `Split Cloud`, `Multi`, `LCAC`;
- история с 01.01.2021;
- количество = `SUM(s.Quantity * mce.FlagAccountingQtyBA)`;
- выручка без IT = `SUM(s.Price - COALESCE(s.AmountUSDIt_ITW, 0))`;
  IT хранится суммой строки, поэтому не умножается на количество.
  Единицы USD и имя `sub.Chanel` подтверждаются существующим
  `admin_motivation/sql/sales_plan.sql` (поле канала исправлено относительно опечатки `Chael`).

Поля и соединения основаны на предоставленном запросе. До проверки в настоящем
DataWH остаётся проверить существование `Subdivisions.Chanel`, уникальность ключей справочников в JOIN.
Специальных признаков предзаказа/возврата в переданном наборе нет: возвраты
учитываются своим знаком, отдельный отбор предзаказов не добавлялся.

## Периоды и правила

Полные календарные годы с 2021 и текущий LTM — последние 12 **завершённых** месяцев.
Например, на 24.10.2026 LTM: 01.10.2025–01.10.2026 (правая граница исключается).
Неполный текущий месяц не включается. Границы видны в отчёте. Альтернативный режим
показывает только полные годы; LTM может пересекаться с прошлым календарным годом.
Часы отчёта — Europe/Moscow.

Активный дилер имеет чистые штуки > 0. Пороги: S ≤ 10, M ≤ 50, L ≤ 250, XL > 250.
Пороговая сегментация всегда использует штуки. ABC использует выбранную меру,
только положительные веса; пересекающий границу дилер остаётся в предыдущей группе.
При равных весах порядок задаётся кодом. Суммы без положительного веса попадают в C.

При масштабе компании ABC/пороги вычисляются до фильтра филиалов; при масштабе
филиала единица наблюдения — (филиал, код дилера). Один код в двух филиалах
в этом режиме считается дважды. Это явно указано на странице.

Новые 2021 года — начальная наблюдаемая база, а не доказательство отсутствия
более ранних продаж. Возврат определяется по наблюдаемой истории. Отбор стартовой
когорты влияет только на потоки и траектории, не меняет общий мост/обзор.
Чистые отрицательные корректировки сохраняются в мосте отдельной категорией;
сумма вкладов строго равна разности итогов. Структура показывает активных дилеров,
поэтому её сумма может отличаться от чистого итога с неактивными возвратами.

## Работа

Первичная загрузка читает помесячную витрину с тайм-аутом 120 секунд.
Успешный результат кешируется на 15 минут (стандартный Django cache);
параллельные начальные чтения сериализованы внутри процесса. Ошибки не кешируются.
При > 500 000 строк неполный результат не отображается — потребуется отдельная
материализованная витрина. При нескольких процессах кеш/блокировка локальны
каждому процессу, если отдельно не настроен общий backend Django cache.

Шесть страниц доступны без внешних JS-библиотек/CDN. Параметры сохраняются в URL,
CSV содержит те же фильтры и сводные таблицы. Карточка ищет по имени/коду,
список ограничен первыми 100 найденными дилерами (выбранный код сохраняется).
Метаданные документов и тип дилера не выводятся: тип дилера указан в ТЗ как этап 2.

## Проверки

`manage.py test dashboards --settings=portal.settings_local --noinput`

Для браузерного теста: `RUN_BROWSER_TESTS=1`, установленный Playwright,
`PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium`.
Тесты используют синтетические данные и подменяют DataWH; корпоративный SQL Server
в этой среде недоступен. Демо-данные в рабочих views не подставляются.
