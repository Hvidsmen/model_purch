# Дашборды / Динамика дилерской базы

Третий проект портала: `/dashboards/`. Доступен ролям
«Администратор» и «Аналитик» в проекте «Дашборды». Общий администратор портала
также имеет доступ. Назначения независимы от Мотивации и Модели закупок.
Данные продаж не записываются в SQLite и не требуют SQL-процедур. Для разделения прав
применяется миграция `base.0005`; снимки обновляются отдельным фоновым заданием портала.

## Источник

Используется существующее подключение `DWH_SQL_CONN_STR` к DataWH.
`sql/dealer_sales.sql` выполняет только SELECT. Данные агрегируются до месяца,
кода дилера, филиала и товарных разрезов; код передаётся отдельно от названия.

Условия, согласованные с заказчиком:

- `sub.Chanel = N'Дилерский'`;
- семь брендов из исходного запроса;
- `Split`, `Split Cloud`, `Multi`, `LCAC`;
- история с 01.01.2021;
- количество = `SUM(s.Quantity * mce.FlagAccountingQtyBA)`;
- выручка без IT = `SUM(s.Price - COALESCE(s.AmountUSDIt_ITW, 0))`;
  IT хранится суммой строки, поэтому не умножается на количество.
  Единицы USD и имя `sub.Chanel` подтверждаются существующим
  `admin_motivation/sql/sales_plan.sql` (поле канала исправлено относительно опечатки `Chael`).

Поля и соединения основаны на предоставленном запросе. До проверки в настоящем
DataWH остаётся проверить существование `Subdivisions.Chanel`, уникальность ключей справочников в JOIN.
Специальных признаков предзаказа/возврата в переданном наборе нет: возвраты
учитываются своим знаком, отдельный отбор предзаказов не добавлялся.

## Периоды и правила

Полные календарные годы с 2021 и текущий LTM — последние 12 **завершённых** месяцев.
Например, на 24.10.2026 LTM: 01.10.2025–01.10.2026 (правая граница исключается).
Неполный текущий месяц не включается. Границы видны в отчёте. Альтернативный режим
показывает только полные годы; LTM может пересекаться с прошлым календарным годом.
Часы отчёта — Europe/Moscow.

Активный дилер имеет чистые штуки > 0. Пороги: S ≤ 10, M ≤ 50, L ≤ 250, XL > 250.
Пороговая сегментация всегда использует штуки. ABC использует выбранную меру,
только положительные веса; пересекающий границу дилер остаётся в предыдущей группе.
При равных весах порядок задаётся кодом. Суммы без положительного веса попадают в C.

При масштабе компании ABC/пороги вычисляются до фильтра филиалов; при масштабе
филиала единица наблюдения — (филиал, код дилера). Один код в двух филиалах
в этом режиме считается дважды. Это явно указано на странице.

Новые 2021 года — начальная наблюдаемая база, а не доказательство отсутствия
более ранних продаж. Возврат определяется по наблюдаемой истории. Отбор стартовой
когорты влияет только на потоки и траектории, не меняет общий мост/обзор.
Чистые отрицательные корректировки сохраняются в мосте отдельной категорией;
сумма вкладов строго равна разности итогов. Структура показывает активных дилеров,
поэтому её сумма может отличаться от чистого итога с неактивными возвратами.

## Обновление данных

Страница отчёта **не обращается к DataWH**. Она читает последний успешно
подготовленный снимок из `.local/dashboards/`. Данные сохраняются в gzip,
указатель на готовый снимок меняется атомарно. При ошибке старый снимок
остаётся доступен; ошибки и возраст данных видны на дашборде.
Сохраняются два готовых файла и история последних 30 запусков.
Блокировка файла исключает параллельные обновления между потоками и процессами.
После перезапуска портала прерванный запуск распознаётся и допускает повтор.

Администратору проекта доступна страница `/dashboards/refresh/`:

- «Обновить сейчас» запускает фоновое чтение DataWH;
- состояние, этап, число прочитанных строк, время и история обновляются
  автоматически каждые 3 секунды;
- ежедневное время задаётся по Москве после завершения обновления Sales;
- расписание **изначально выключено**, поскольку время источника ещё не согласовано;
- аналитик может смотреть статус и историю, но не запускать или настраивать задание.

При обычном запуске `start.ps1` / `portal-task.ps1` планировщик запускается вместе
с `runserver --noreload`, не требует отдельной Windows-учётной записи и работает,
пока работает портал. Пропущенный запуск догоняется при старте. Успешный или
неуспешный запуск в текущем окне не повторяется автоматически до следующего дня;
ручной повтор доступен администратору. Для WSGI-развёртывания можно включить
`DASHBOARDS_SCHEDULER=1` либо вызывать команду внешним планировщиком:

```
python manage.py refresh_dealer_dashboard --settings=portal.settings_local
```

Чтение DataWH ограничено 120 секундами на SQL-запрос. При > 500 000 месячных
строк неполный результат не публикуется: понадобится отдельная витрина.
Запрос не дробит строки по неиспользуемым Range/PlanningGroup, но сохраняет
все разрезы, необходимые отчёту: месяц, код, филиал, бренд, оборудование, география.
Память Django cache используется только для ускорения чтения/пересчёта;
перезапуск портала не удаляет успешный файловый снимок.

## Интерфейс

Все шесть страниц работают без внешних JS-библиотек/CDN. Филиал, бренд и
оборудование выбираются выпадающими списками с поиском, галочками, «Выбрать всё»
и «Снять всё». Пустой выбор означает отсутствие фильтра. Границы S/M/L можно
менять (по умолчанию 10/50/250); XL — всё выше L. Проверяется `0 < S < M < L`.
Пороговые настройки применяются ко всем страницам и CSV и сохраняются в ссылке;
они не меняют сегментацию ABC. Параметры сохраняются в URL. На время чтения
снимка и пересчёта фильтры заблокированы, показывается фактическое прошедшее время.

Карточка ищет по имени/коду; список ограничен первыми 100 найденными дилерами
(выбранный код сохраняется). Метаданные документов и тип дилера не выводятся:
тип дилера указан в ТЗ как этап 2.

## Проверки

`manage.py test dashboards --settings=portal.settings_local --noinput`

Для браузерного теста: `RUN_BROWSER_TESTS=1`, установленный Playwright,
`PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium`.
Тесты используют синтетические данные и подменяют DataWH; корпоративный SQL Server
в этой среде недоступен. Демо-данные в рабочих views не подставляются.
