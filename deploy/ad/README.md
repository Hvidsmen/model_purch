# Вход в Active Directory без IIS

Режим использует обычную форму портала и LDAPS. IIS, RSAT, служебная учётная запись для чтения каталога и системные LDAP-библиотеки не требуются. ldap3 устанавливается в существующую виртуальную среду без прав администратора Windows.

Локальные имена (`admin`) проверяются как раньше в Django. Доменный вход выполняется только для `DAICHI\username` или `username@daichi.local`. При ошибке AD нет перехода на локальный пароль для такого имени. Пароли AD не сохраняются в SQLite, сессии или журналах. Пользователь после AD-bind дополнительно ищется в каталоге: имя в портале берётся из настоящего sAMAccountName, поэтому UPN и DOMAIN\login приводят к одной записи.

## Что необходимо

- DNS-имя контроллера домена с доступным LDAPS-портом 636. DNS-имя должно совпадать с сертификатом сервера. Не подставляйте случайный IP или просто имя домена вместо проверенного DC.
- Действительный серверный сертификат и доверие к корпоративному CA на машине портала. Если CA отсутствует в хранилище Python, получите у администратора **публичную** цепочку CA в PEM и укажите её файл. Проверка сертификата и имени сервера обязательна.
- HTTPS между браузером и порталом: LDAPS защищает только участок портал→AD. Доменный пароль нельзя вводить на нынешнем HTTP-адресе runserver. При HTTP приложение не принимает доменный вход, но локальный вход работает как раньше.

Проверить имя DC без административных прав:

```powershell
Resolve-DnsName -Type SRV _ldap._tcp.dc._msdcs.daichi.local
# Затем для фактического NameTarget из результата:
Test-NetConnection dc01.daichi.local -Port 636
```

Проверка порта не доказывает корректность сертификата. Пароли передавать в чат или командную строку не нужно.

## Установка и конфигурация

Из корня проекта:

```powershell
.\.venv310\Scripts\python.exe -m pip install -r requirements-ad.txt
```

В окружении процесса портала настройте (имя DC ниже — **пример**, замените фактическим):

```powershell
$env:PORTAL_AD_AUTH = 'true'
$env:PORTAL_AD_LDAPS_URL = 'ldaps://dc01.daichi.local:636'
$env:PORTAL_AD_NETBIOS_DOMAIN = 'DAICHI'
$env:PORTAL_AD_UPN_SUFFIX = 'daichi.local'
$env:PORTAL_AD_SEARCH_BASE = 'DC=daichi,DC=local'
# При необходимости — публичная цепочка CA, а не закрытый ключ:
$env:PORTAL_AD_CA_CERT_FILE = 'C:\Portal\certs\corporate-ca.pem'
# При работе портала через HTTPS:
$env:DJANGO_SECURE_COOKIES = 'true'
```

Если CA уже доверен Python, PORTAL_AD_CA_CERT_FILE не нужен. PORTAL_WINDOWS_AUTH не включайте: это другой режим, предназначенный для IIS.

Перезапустите сервер в этом окружении. Полное развёртывание HTTPS зависит от сертификата и способа размещения портала; HTTPS-шлюз должен быть настроен администратором инфраструктуры либо нужно использовать отдельный HTTPS-сервер с доверенным сертификатом. Обычный start.ps1 запускает HTTP и сам HTTPS не добавляет. Доверие к произвольным заголовкам X-Forwarded-Proto не включено: схема должна быть корректно передана доверенным HTTPS-шлюзом в WSGI. Для прямого HTTPS-входа можно использовать сервер из следующего раздела.

## Права

При первом успешном доменном входе создаётся `daichi\samaccountname`, без локального пароля, без административных прав и без роли. Администратор назначает роль через обычный экран пользователей. Ранее созданная Windows-учётная запись с таким полным именем используется повторно; обычный локальный `admin`/`samaccountname` не связывается автоматически с доменной записью.

Деактивированная запись портала не входит. AD проверяет пароль, блокировки и состояние доменной записи при новом входе. Уже открытая сессия Django не опрашивает AD на каждом запросе: для немедленного отзыва доступа отключите пользователя в портале и используйте доменную/сеансовую политику организации. Группы AD и роли портала пока не синхронизируются.

## Проверка

1. Обычный локальный вход работает при включённом AD.
2. По HTTPS оба формата доменного имени приводят к одной записи.
3. Неверный пароль, недоступный DC, недоверенный сертификат, несколько найденных записей и отключённая запись дают отказ, не создавая пользователя.
4. До назначения роли разделы проектов недоступны; после назначения действуют существующие права.

Автотесты проверяют Django и вызовы LDAP-клиента с имитацией ответов; реальная сеть daichi.local и сертификат DC из среды разработки недоступны.

## Прямой HTTPS без IIS

В `requirements-ad.txt` включены Cheroot и WhiteNoise. Скрипт `serve_https.py` обслуживает Django и собранную статику, не запускает отладчик, требует TLS 1.2+ и включает secure cookies. Нужны серверный сертификат с подходящим DNS-именем и соответствующий закрытый ключ в PEM. Получите их через установленную в организации процедуру; **не присылайте закрытый ключ или пароли в чат и не кладите их в Git**. Для входа из браузера сертификат должен быть доверенным, а не принятым через предупреждение браузера.

Один раз задайте постоянный случайный `DJANGO_SECRET_KEY` в защищённом окружении процесса. Не меняйте его при каждом запуске. Разрешите реальное имя портала:

```powershell
$env:DJANGO_ALLOWED_HOSTS = 'portal.daichi.local,localhost,127.0.0.1'
$env:PORTAL_WINDOWS_AUTH = 'false'
.\.venv310\Scripts\python.exe manage.py migrate --settings=portal.settings_local
.\.venv310\Scripts\python.exe manage.py collectstatic --noinput --settings=portal.settings_local
.\.venv310\Scripts\python.exe serve_https.py --certificate C:\Portal\certs\portal-chain.pem --private-key C:\Portal\certs\portal-key.pem --address 0.0.0.0 --port 8443 --database .\db.sqlite3
```

Открывайте `https://portal.daichi.local:8443` (пример имени — замените реальным). Для локальной проверки оставьте `--address 127.0.0.1`. Если входящий порт блокируется брандмауэром, доступ к нему согласует администратор сети; административные права для самого процесса Python не нужны. Не запускайте одновременно старый HTTP-процесс с доменной формой: перед переключением остановите его.

Запуск не требует IIS и не устанавливает службу Windows. Для постоянной работы процесс должен запускаться и перезапускаться подходящим средством эксплуатации. Загруженные media-файлы этим сервером не публикуются автоматически: доступ к ним следует предоставлять через защищённые маршруты приложения.

Проверить LDAPS до ввода пароля (после настройки переменных окружения):

```powershell
.\.venv310\Scripts\python.exe manage.py check_ad_connection --settings=portal.settings_local
```

Команда проверяет DNS, TCP и TLS с проверкой сертификата/имени. Она не передаёт пароль и не проверяет права поиска пользователей.
