# Отмена прерванного расчёта

Перезагрузка процесса не сбрасывает статусы AlgorithmRun/AlgorithmStep. На странице проверки расчёта кнопка «Отменить остановленный расчёт» закрывает такой запуск, включая шаг, оставшийся running. Запуск становится cancelled, прерванные running-шаги — failed с объяснением, pending-шаги — skipped. Завершённые шаги и их результаты сохраняются. Уже выполненные операции в MS SQL/OLAP не отменяются этой кнопкой; новый запуск повторяет алгоритм.

Выполнение шага и отмена используют одну неблокирующую OS-блокировку на run_id. Живой шаг получает HTTP 409 на повторное исполнение и отмену. При падении процесса ОС освобождает блокировку: наличие файла не означает, что расчёт продолжает работать. После сбоя продолжать следующие шаги нельзя — сначала отменить запуск и создать новый. Нет автоматического сброса по таймеру, который мог бы отменить долгий действующий SQL/OLAP-шаг.

Файлы находятся в BASE_DIR/.local/algorithm-locks (настройка ALGORITHM_LOCK_DIR позволяет переопределить каталог); удалять их при работающем сервере нельзя. Реализация для одного сервера/общей локальной файловой системы, с flock на Linux и msvcrt.locking на Windows. Если серверов несколько, нужен общий механизм блокировок. После обновления старые процессы портала должны быть остановлены: предыдущая версия не удерживала такие блокировки.

Проверки: запрет отмены и параллельного шага при удерживаемой блокировке, отмена running-записи без живого процесса, сохранение истории и разрешение нового запуска. Отдельный процесс удерживает блокировку, тест принудительно завершает его и подтверждает освобождение без удаления файла. Проверка Windows-ветки требует запуска теста на Windows.
