# Ожидание задания ModelPurch

Шаг 5 запускает SQL Server Agent job ModelPurch через sp_start_job и опрашивает историю каждые 5 секунд, без фиксированной минутной паузы. Перед стартом запоминаются job_id, сессия Agent и максимальный instance_id итоговой записи задания (step_id = 0). Успех требует новой итоговой записи run_status = 1; успешный отдельный шаг или старая история не завершают ожидание. Ошибка/отмена (0/3) передаются в историю расчёта с сообщением Agent. Если задание уже запрошено/выполняется, повторный запуск не отправляется. Перезапуск Agent во время ожидания является ошибкой, а не успехом.

По умолчанию таймаут — 3600 секунд, настройка Django OLAP_JOB_TIMEOUT_SECONDS позволяет изменить его. Отдельный SQL-запрос ограничен 30 секундами. Таймаут, остановка веб-сервера и разрыв наблюдения не останавливают job на SQL Server: перед повторным запуском следует проверить его состояние. Отмены sp_stop_job приложение не отправляет. Соединение закрывается во всех случаях; запуск и чтение системных таблиц идут в autocommit.

SQL-пользователю портала необходимы права на запуск job и чтение msdb.dbo.sysjobs/sysjobactivity/syssessions/sysjobhistory. Отсутствие прав не заменяется фиктивным успехом. Проверка предполагает, что job выполняет обработку куба синхронно: если сам job запускает другую асинхронную задачу, завершение Agent job ещё не подтверждает завершение той задачи.

Тесты проверяют ожидание/успех/ошибку/отмену/таймаут/перезапуск Agent/занятое задание и закрытие соединения. Дополнительно SQL фильтра истории проверяется на изолированной SQLite-таблице. На корпоративном SQL Server job из этой среды не запускался; синтаксис и права требуют проверки в целевой среде.
