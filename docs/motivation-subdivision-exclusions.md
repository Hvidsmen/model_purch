# Shared motivation subdivision exclusions

The version-independent portal reference is `MotivationSubdivisionExclusion` (migration 0043). Manage it in Мотивация → Справочники → Справочник исключений (the Django admin reference remains available). Motivation editors can add names, edit comments and toggle enabled; other roles cannot mutate the reference. Rows have SubdivisionName, enabled and comment; the admin checks trimmed case-insensitive duplicates. Initial enabled names: E-Com, Retail, Брендинг, Прочее, СНГ, Д-Маврикий, Буфер, Вентиляция, ДПП. SubdivisionName ДПП is excluded for every motivation type; independently, channel/group exclusions are configured by coefficient type in the shared references introduced in migration 0045. Their initial values exclude channel ДПП and PlanningGroupSalesERP HEAT only for policies. See [per-coefficient group/channel rules](motivation-dimension-exclusions.md).

No version/year/source field exists on the reference. Authenticated requests and public import/calculation/report entry points load a fresh DB snapshot into a ContextVar; nested helpers reuse it. An operation never changes scope halfway through because an administrator edits the reference. Helpers used purely to generate SQL can use the initial defaults outside an operation; production entry points establish the database context. SQL literals are quoted centrally. Empty enabled lists allow all names. SubdivisionKey is only the source join identity; scope filtering and motivation aggregation use SubdivisionName. The active subdivision manager also tests names, never physical keys.

The same predicate is used for planning/ERP imports, fact consumption in native calculation preparation, all motivation types, policy author allocation/eligibility and report readers. The old native exclusion DELETE is structurally recognized and replaced with the shared predicate for every coefficient type. Static SQL snippets carry a scope placeholder resolved before execution, including author-share caching and progress boundary recognition. The original reviewed SQL/template list is retained only as a structural compatibility guard, not an active business list.

Import preserves the full participating plan and physical channel receipts. O0–O4 remain full amounts; channel segment vectors allow independent bases for policies, sales and directors under the current references. P0–P4 remain legacy compatibility metadata. Group/channel changes apply on recalculation rather than irreversibly removing source amounts. Older plans lacking channel provenance require a reload when channel rules change; older imports also omitted DPP entirely. Saved financial run snapshots are not rewritten.

Scope fingerprints include enabled names and per-coefficient group/channel rules and invalidate compact summary/configuration fingerprints on the next operation. New private runs retain the exact excluded names and fingerprint in inputs/Excel. After deployment apply migrations 0043–0045, reload saved plans and rerun calculations. Existing SQL Agent procedures/views are regenerated when the job is saved or manually started; after changing the directory, save the existing automatic jobs once before their next scheduled run so stored SQL uses the new dictionary snapshot. Previously saved financial results are not recalculated by editing a reference.

Validation covers dictionary edits/empty lists/quoting, operation stability, name-vs-key identity, both plan sources, channel-specific policy bases, native SQL generation, admin permissions and calculation/report regression suites. There is no live SQL Server connection in the development environment: generated T-SQL still requires observation on DWH after deployment.

Migration 0044 repairs already installed directories: it creates the ДПП exclusion if missing, or enables existing case/space variants without replacing comments or changing other exclusions. This also fixes the initial seed and pure rule defaults. Rerun private scenarios after applying the migration; already imported plan rows are filtered before rate/director coverage validation.
