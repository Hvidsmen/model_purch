# Per-coefficient group and channel exclusions

Migration 0045 adds two version-independent references: MotivationPlanningGroupExclusion and MotivationChannelExclusion. Both contain coefficient_type (Политики, Продажи, Директора), value, enabled and comment. The motivation sidebar exposes «Исключения групп планов продаж» and «Исключения каналов». Motivation editors can add/edit/disable rules; reader roles cannot write. Django admin also exposes the references.

Initial data is inserted automatically: HEAT for Политики in the group reference, ДПП for Политики in the channel reference. Sales/directors have no initial exclusions. The migration is idempotent and does not re-enable an existing disabled row. Group names match PlanningGroupSalesERP after case/space/leading-number normalization (HEAT and 5. HEAT match). Channels match Chanel case-insensitively after trimming. Rules are exact matches, scoped independently to each coefficient type; a matching group OR channel excludes a row. An empty enabled reference removes that dimension's exclusions. The separate SubdivisionName reference remains common to all types, including subdivision ДПП; disabling a channel rule does not re-include an excluded subdivision.

The shared helper motivation_exclusions supplies Python participation and equivalent quoted T-SQL. The request/operation exclusion scope loads all three references once into immutable ContextVar snapshots. A mid-run edit affects the next operation. Scope fingerprints include enabled group/channel rules and invalidate compact summaries/configuration freshness. Native procedure preparation replaces legacy fixed DELETE filters with the generated per-type predicate; 2026 transition windows, 2025 exact/broad author shares, rate-availability guards, performance readers and director fact readers consume the same rules. Legacy literals retained in structural patch guards identify the reviewed source, not the active exclusion policy.

Source imports preserve the full participating plan and channel receipts. O0–O4 stay full amounts; channels stores the original segment vectors by channel. Bases for all three coefficient types are derived from these full vectors at calculation time, not irreversibly subtracted at import. Local/global plans, director plans, compact comparisons, balancing, private 100% scenarios and 2025 director calculations use independent bases. A sales exclusion does not remove a director's source fact: director calculations reuse raw unreplicated sales fact with the director predicate, before any sales participation filtering. Available native classifications are retained for actual groups/channels absent from the plan; participation is not inferred solely from planned groups. New run/SQL Agent metadata records the active rules; Excel retains that snapshot.

Older plans without original channel receipts cannot safely evaluate changed channel rules. When those rules differ from the initial configuration, missing channel provenance stops the calculation with an instruction to reload the plan once. Group-only changes do not require new channel metadata. Plans already loaded with channel receipts can be recalculated after rule changes, including restoring previously excluded amounts, without reimporting. Existing saved financial results remain unchanged until recalculation.

Deployment: update the portal and apply migration 0045. Default rows need no manual setup. Recalculate saved plans and motivation scenarios; save automatic SQL Agent jobs once so their stored procedure/view snapshots use the current rules. Repeat that save after later reference edits before the next automatic run. The reference does not modify the original DWH subdivision/product catalogs or original source procedure.

Validation covers default/empty/disabled references, numeric group aliases, SQL/Python equivalence across types, quoted values, snapshot stability, UI permissions and duplicate validation, changing/restoring bases on an existing loaded plan, missing legacy channel provenance and independent director actuals when sales are excluded. Generated SQL is tested against existing templates and SQLite mathematical projections/mocked ODBC; a live SQL Server connection is unavailable in this workspace.
