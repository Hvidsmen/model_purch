# SPLIT: физические остатки и ожидаемые приходы

В черновике сценария на вкладке **«Сток и закупки»** сразу показаны все группы. Нажмите **«Загрузить остатки и приходы всех групп»** для общей загрузки из DataWH. В единой таблице нажмите на группу, чтобы раскрыть мощности и редактировать внутренние/наружные блоки. Кнопка **«Сохранить группу»** сохраняет её поля таблицы и месячного прогноза. Прогнозы, закупки и канальные планы при загрузке источника не меняются. Сначала сохраните их ручные правки.

## Количество

`FlagAccountingQtyBA=1` для наружных и `0` для внутренних используется в ModelPurch для учёта комплектов. Умножать на него физические количества в этой форме нельзя: иначе внутренние блоки обнуляются, а расчёт комплекта по минимуму двух типов блоков неверен.

Для SPLIT считаются **физические штуки каждого типа**. Флаг не участвует в умножении. При этом сохранён отбор существующих моделей через ModelCodeERP, но как EXISTS, чтобы дубли справочника не умножали количество. Закупочный модуль и его агрегаты Stock/Incomes этим изменением не переписываются.

Модели связываются по ERP-ссылке с сохранённым составом группы сценария. Тип блока и мощность сверяются с классификацией источника. Количества суммируются по всем моделям каждой мощности и типа блока. Новая модель, изменённая классификация или неоднозначная связь не скрываются: загрузка отменяется до обновления справочников и снимка состава. Товарная область — «Бытовые кондиционеры».

## Источники и дата

Все запросы — SELECT из DataWH: `erp.StreamGoods`, номенклатура, склады и ModelCodeERP. Таблицы ModelPurch не удаляются, не пересоздаются и не обновляются.

`ReportDate` равен **дате фактического стока текущего сценария**, показанной в форме. Глобальная `ModelPurch.dbo.Parametrs` не меняется и не подменяет выбранную историческую дату. Если среза StreamGoods нет, загрузка отменяется; прежние значения не заменяются нулями. При наличии среза отсутствие положительных подходящих строк даёт явные нули.

Остаток: склады с `даичи_НазначениеСклада = 'Продажа'`, сумма `ВНаличии + ВПути` по модели. МВМ отдельным условием не добавляется. Сохраняется исходный HAVING положительного количества.

Приход: сумма `ВПути + КПоступлению`. Отбор типов из предоставленного SQL ModelPurch:

- `ЗаказПоставщику` и `ПриобретениеТоваровУслуг` — независимо от назначения склада;
- `ПеремещениеТоваров` — только при назначении склада, отличном от «Продажа»; NULL назначения, как в исходном SQL, не проходит сравнение `<>`;
- остальные типы не включаются.

Правило даты повторяет исходное выражение SQL Server. Если `ДатаПоступления <= ReportDate`, берётся `ReportDate + 14 дней`, иначе исходная дата. Для `ЗаказПоставщику` к полученной дате дополнительно прибавляются **два календарных месяца** (не 60 дней). Для остальных типов дополнительных двух месяцев нет. Проверка статуса «Отгружен» к этим правилам не добавляется.

Приходы с ожидаемой датой после среза и до начала планирования попадают в «Поступит до начала», с начала по конец плана включительно — в «Поступит в периоде». После конца плана не прибавляются и показаны отдельным количеством в информации об источнике. NULL даты или количества отменяют загрузку без частичного сохранения групп, вместо произвольного распределения либо нулей.

## Сохранение и права

Загрузка требует обычных административных прав планирования SPLIT и POST с CSRF. Утверждённый сценарий и устаревшая ревизия не загружаются. После чтения источника повторная проверка ревизии не позволяет перезаписать параллельные изменения. В состоянии сохраняются источник, дата стока, время загрузки, база количества и количество после периода; в журнале сценария — автор и событие. Ручное сохранение после загрузки отмечается как ручная корректировка данных источника.

## Проверки

Исполняемые тесты исходных агрегаций проверяют ненулевое количество внутренних блоков при флаге 0, отсутствие умножения на дубли ModelCodeERP, склады/типы документов, перенос просроченной даты, два календарных месяца и NULL. Проверки сценария подтверждают границы периодов, сохранение планов и прогнозов, отказ без среза/даты/модели, защиту утверждённой версии и ревизии. Chromium проверяет заполнение формы после нажатия кнопки.

Корпоративная DataWH из облачной среды недоступна. Реальная загрузка выполняется на сервере портала от его служебной SQL-учётной записи; соответствие полей и данных источника подтверждается первым запуском на сервере.


## Единая таблица

Сток, приходы до начала, прогноз, итог на начало, приходы в периоде, суммарный план каналов и комплекты на конец теперь находятся **в одной таблице**. Строки групп содержат итоги, нажатие на название раскрывает строки мощностей и редактор группы. Строка группы и её мощности не складываются между собой повторно: общий итог считается по группам.

Внутри каждой строки мощности рядом видны вводимые физические количества и рассчитанный результат. Под мощностями раскрываются месяцы прогноза, дополнительные закупки, кнопка сохранения, источник и плановые количества каждого канала. Прогноз мощности может задаваться напрямую либо рассчитываться из общего прогноза группы по долям. Запас общий для каналов, суммарный план расходует его один раз.

Шапка и первый столбец закреплены внутри прокручиваемой области. Строки мощностей по умолчанию скрыты, после сохранения редактируемая группа остаётся раскрытой. Расчётные числа обновляются после сохранения. Итоги конца периода берутся из существующего основного расчёта; если он неполон, показано «—». Базовые формулы остатков сохраняются; способ ввода прогноза хранится вместе со сценарием.


## Общая загрузка и сохранение

«Загрузить остатки и приходы всех групп» читает весь состав сценария одним SQL-подключением: проверка среза и два агрегирующих SELECT на пакет до 500 групп. Все имена параметризованы. При ошибке хотя бы одной группы загрузка не сохраняется частично. Прогнозы, закупки и канальные планы не заменяются.

У каждой группы своя HTML-форма, поэтому одноимённые поля соседних групп не смешиваются. Большой сценарий не отправляет тысячи полей одной POST-формой. Нажатие «Сохранить группу» сохраняет все её вводимые количества, месячный прогноз и дополнительные закупки, после чего пересчитываются итоги. Сначала сохраняйте правки одной группы, затем переходите к следующей: несохранённые изменения не являются частью снимка сценария.

## Расчёт начала и конца

На начало: сток на срез + поступления до начала − прогноз до начала. Поступления и дополнительные закупки внутри периода не прибавляются к началу. Общий прогноз распределяется точным алгоритмом по долям; прямые значения мощностей используются без распределения. Один комплект уменьшает оба типа блоков на одну штуку. Комплекты — минимум двух типов блоков каждой мощности, итог группы — сумма этих минимумов. Разные мощности и группы не соединяются в комплекты между собой.

Начало рассчитывается независимо от цен, плановых продаж и будущих поступлений. Недостающий сток/приход/прогноз и неполный импорт прогноза дают «—», а не вымышленные нули. Для ненулевого общего прогноза нужна сумма долей мощностей 100%; прямой прогноз мощностей, нулевой прогноз и отсутствие промежутка не требуют распределения. Отрицательные результаты остаются видимым дефицитом.

План продаж в таблице — сумма каналов, а его мощности и остаток на конец берутся из существующего основного расчёта. Общий запас не умножается по количеству каналов. Формулы основного расчёта и сохранённая структура сценария не меняются.


## Ввод прогноза группы и мощностей

Столбец **«Прогноз до начала»** теперь содержит поля ввода и в строке группы, и в строках мощностей. Общую сумму группы можно ввести и сохранить, не раскрывая её. Прямой прогноз мощности вводится после раскрытия. Внутри строки настроек виден текущий способ «По группе» / «По мощностям».

- Правка общего значения включает прогноз **по группе**. Ненулевой общий прогноз распределяется по сохранённым долям мощностей, сумма которых должна быть 100%. Если долей нет, общая введённая сумма сохраняется и показывается, но расчёт мощностей остаётся неизвестным с пояснением.
- Правка мощности включает прямой прогноз **по мощностям**. Доли плановых продаж для такого прогноза не требуются. Общий прогноз — сумма введённых значений; отсутствующее значение не заменяется нулём. По уже заполненным мощностям начало рассчитывается, даже если соседняя мощность ещё не заполнена.
- Помесячный ввод группы сохранён как альтернатива в раскрывающемся блоке. Правка месяца включает месячный способ, общий итог — сумма месяцев; распределение по мощностям использует доли. Последняя правка прогноза выбирает активный способ. Итоги остатков пересчитываются после сохранения.

Открывающий и основной конечный баланс используют один общий обработчик прогноза, поэтому ручные мощности не теряются при расчёте конца. Если план продаж и дополнительные закупки равны нулю, прямой прогноз по мощностям или нулевой общий прогноз позволяет рассчитать физический конец без долей; ненулевые плановые продажи/закупки по-прежнему требуют своего распределения. В прямом способе учитываются и мощности с нулевой плановой долей. Между датой стока и началом плана нет промежутка — предшествующий прогноз равен нулю.

Сохранение только стока не стирает прежние месячные прогнозы и не подтверждает неполный импорт автоматически. Загрузка прогноза из утверждённого сценария включает месячный способ для затронутых групп. Утверждение, коррекции и ревизии сохраняют эти значения обычным снимком. Новые поля JSON необязательны: прежние сценарии продолжают использовать месячный способ без миграции базы.
