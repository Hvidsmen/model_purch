# SPLIT: физические остатки и ожидаемые приходы

В черновике сценария на вкладке **«Сток и закупки»** выберите группу и нажмите **«Загрузить остатки и приходы из DataWH»**. Загружается выбранная группа сразу для всех каналов: остатки и приходы разделяются по мощности, внутренним и наружным блокам. Загрузка заменяет шесть соответствующих полей; сохранённые прогноз продаж, дополнительные закупки, планы каналов и другие группы не меняются. Перед загрузкой сохраните несохранённые ручные изменения прогноза/закупок.

## Количество

`FlagAccountingQtyBA=1` для наружных и `0` для внутренних используется в ModelPurch для учёта комплектов. Умножать на него физические количества в этой форме нельзя: иначе внутренние блоки обнуляются, а расчёт комплекта по минимуму двух типов блоков неверен.

Для SPLIT считаются **физические штуки каждого типа**. Флаг не участвует в умножении. При этом сохранён отбор существующих моделей через ModelCodeERP, но как EXISTS, чтобы дубли справочника не умножали количество. Закупочный модуль и его агрегаты Stock/Incomes этим изменением не переписываются.

Модели связываются по ERP-ссылке с сохранённым составом группы сценария. Тип блока и мощность сверяются с классификацией источника. Количества суммируются по всем моделям каждой мощности и типа блока. Новая модель, изменённая классификация или неоднозначная связь не скрываются: загрузка отменяется до обновления справочников и снимка состава. Товарная область — «Бытовые кондиционеры».

## Источники и дата

Все запросы — SELECT из DataWH: `erp.StreamGoods`, номенклатура, склады и ModelCodeERP. Таблицы ModelPurch не удаляются, не пересоздаются и не обновляются.

`ReportDate` равен **дате фактического стока текущего сценария**, показанной в форме. Глобальная `ModelPurch.dbo.Parametrs` не меняется и не подменяет выбранную историческую дату. Если среза StreamGoods нет, загрузка отменяется; прежние значения не заменяются нулями. При наличии среза отсутствие положительных подходящих строк даёт явные нули.

Остаток: склады с `даичи_НазначениеСклада = 'Продажа'`, сумма `ВНаличии + ВПути` по модели. МВМ отдельным условием не добавляется. Сохраняется исходный HAVING положительного количества.

Приход: сумма `ВПути + КПоступлению`. Отбор типов из предоставленного SQL ModelPurch:

- `ЗаказПоставщику` и `ПриобретениеТоваровУслуг` — независимо от назначения склада;
- `ПеремещениеТоваров` — только при назначении склада, отличном от «Продажа»; NULL назначения, как в исходном SQL, не проходит сравнение `<>`;
- остальные типы не включаются.

Правило даты повторяет исходное выражение SQL Server. Если `ДатаПоступления <= ReportDate`, берётся `ReportDate + 14 дней`, иначе исходная дата. Для `ЗаказПоставщику` к полученной дате дополнительно прибавляются **два календарных месяца** (не 60 дней). Для остальных типов дополнительных двух месяцев нет. Проверка статуса «Отгружен» к этим правилам не добавляется.

Приходы с ожидаемой датой после среза и до начала планирования попадают в «Поступит до начала», с начала по конец плана включительно — в «Поступит в периоде». После конца плана не прибавляются и показаны отдельным количеством в информации об источнике. NULL даты или количества отменяют загрузку всей выбранной группы, вместо произвольного распределения либо нулей.

## Сохранение и права

Загрузка требует обычных административных прав планирования SPLIT и POST с CSRF. Утверждённый сценарий и устаревшая ревизия не загружаются. После чтения источника повторная проверка ревизии не позволяет перезаписать параллельные изменения. В состоянии сохраняются источник, дата стока, время загрузки, база количества и количество после периода; в журнале сценария — автор и событие. Ручное сохранение после загрузки отмечается как ручная корректировка данных источника.

## Проверки

Исполняемые тесты исходных агрегаций проверяют ненулевое количество внутренних блоков при флаге 0, отсутствие умножения на дубли ModelCodeERP, склады/типы документов, перенос просроченной даты, два календарных месяца и NULL. Проверки сценария подтверждают границы периодов, сохранение планов и прогнозов, отказ без среза/даты/модели, защиту утверждённой версии и ревизии. Chromium проверяет заполнение формы после нажатия кнопки.

Корпоративная DataWH из облачной среды недоступна. Реальная загрузка выполняется на сервере портала от его служебной SQL-учётной записи; соответствие полей и данных источника подтверждается первым запуском на сервере.
