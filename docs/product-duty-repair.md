# Адресное исправление пошлин товаров без резервных копий

Команда `repair_product_duties` предназначена для проверенного CSV-отчёта
пошлин. Она не меняет справочник групп и не подставляет его нулевые значения
вместо индивидуальных ставок. Резервные копии и дополнительные файлы не создаются.

Из отчёта выбираются только строки PRODUCT без отметки архива с проверенными
ошибочными коэффициентами 5, 6.5, 9 или 10. Их правильные коэффициенты — 0.05,
0.065, 0.09 и 0.1. Более низкие индивидуальные ставки, отсутствующие группы и
архивные строки не исправляются. Другие высокие ставки требуют отдельной проверки.

Для отчёта `duty-audit-20261127-151040.csv` выбраны 68 ID: 38 товаров сценария 5
и 30 товаров сценария 8. 34 архивные и 105 прочих строк пропускаются. Эти ID
не зашиты в код и берутся только из переданного отчёта.

## Запуск из каталога проекта в PowerShell

Предварительный пересчёт без записи; результат остаётся только в памяти PowerShell:

```powershell
$audit = '.local\diagnostics\duty-audit-20261127-151040.csv'
$preview = .\.venv310\Scripts\python.exe manage.py repair_product_duties --audit $audit --json | ConvertFrom-Json
if ($LASTEXITCODE -ne 0 -or -not $preview.preview_hash) { throw 'Предварительный пересчёт не выполнен.' }
$preview.rows | Format-Table id, scenario_id, product, old_rate, new_rate, ddp_before, ddp_after -AutoSize
$preview | Select-Object selected, changed, archived_skipped, other_skipped
```

Применить показанные изменения без резервных копий:

```powershell
.\.venv310\Scripts\python.exe manage.py repair_product_duties --audit $audit --apply --expected-preview $preview.preview_hash
```

Если между запусками изменились товары, ставки, логистика или тип поставщика,
команда остановится без записи и попросит повторить предварительный пересчёт.
Проверяются ID, сценарий, группа и наименование каждого товара. Фактически
архивированный сценарий блокирует запись даже при устаревшей отметке в CSV.
Ставка, уже исправленная на точное целевое значение, не делится ещё раз: проверяется
стоимость, и при необходимости пересчитываются только устаревшие расчётные поля.
Другая новая индивидуальная ставка блокирует всю операцию.

Сценарии, товары и имеющиеся зависимости логистики/поставщиков блокируются
на время операции. Любая ошибка отменяет всю запись. DDP, KDDP и остальные
расчётные поля пересчитываются штатной формулой по текущим параметрам сценария.
При отсутствии логистики запись запрещена. После выполнения обновите страницу
и подготовьте изменённые данные обычным способом на странице расчёта.

Миграция базы не требуется. Обновление кода само по себе не меняет рабочие данные.
