# Пошлина: проценты в интерфейсе, коэффициент в расчёте

В справочнике групп ввод `10` означает 10%. Форма сохраняет коэффициент `0.1`
и при повторном открытии показывает `10`. Таблица товаров уже использует такой
же ввод. Копирование ставки из группы не делит коэффициент повторно; формулы
расчёта продолжают работать с коэффициентом. Excel хранит `0.1` с форматом
`0.00%`, отображает 10% и при обратном импорте сохраняет `0.1`.

Старый справочник сохранял введённое число без преобразования: ввод `10`
превращался в коэффициент `10`, то есть 1000%. Обновление интерфейса намеренно
не меняет существующие ставки автоматически. Старые Excel-файлы с таким
значением остаются ошибочными; после исправления данных сделайте новую выгрузку.

## Проверка и исправление ранее сохранённых значений

Из каталога проекта, предварительный список подозрительных ставок:

```powershell
.\.venv310\Scripts\python.exe manage.py repair_duty_percent
```

Список содержит ставки выше 100%, которые требуют проверки, но не обязательно
являются ошибочными. Никакие данные не меняются.

Для известной ошибки Chillers: в базе сохранено `10`, правильная пошлина — 10%.
Предварительный просмотр покажет товары, сценарии и DDP до/после:

```powershell
.\.venv310\Scripts\python.exe manage.py repair_duty_percent --group Chillers --from-rate 10 --to-percent 10
```

Применение с обязательной резервной копией:

```powershell
$repairBackup = '.local\backups\duty-chillers-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.json'
.\.venv310\Scripts\python.exe manage.py repair_duty_percent --group Chillers --from-rate 10 --to-percent 10 --apply --backup-file $repairBackup
```

Исправляются группа и только её товары в действующих сценариях с той же
ошибочной ставкой. Другие индивидуальные ставки и архивы сохраняются. Перед
записью JSON содержит исходную ставку группы, ID/сценарии товаров, старые
расчётные поля и предварительные новые значения. Существующий файл не
перезаписывается. Изменения выполняются транзакционно; несовпадение исходной
ставки, ошибка цены или резервного файла отменяет исправление. Повторный запуск
со старым исходным значением не делит исправленные ставки ещё раз.

Для примера EXW 17589.36849, объёма 36, контейнера 54, фрахта 10500, таможенной
ставки 22% и доставки 700: DDP меняется с 84562.31 до 31006.66 USD. Формула
ценообразования не меняется. После исправления подготовьте изменённые данные
обычным способом на странице расчёта.

Миграция базы для этого исправления не требуется. Рабочие данные изменяются
только при явном запуске команды с `--apply` на соответствующем сервере.
