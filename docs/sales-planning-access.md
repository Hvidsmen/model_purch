# Доступ к модели планирования продаж

В формах пользователя и группы доступа есть отдельный проект «Модель планирования продаж». Роли проекта не открывают остальные приложения портала.

- **Администратор** проекта работает со всеми сценариями, обновляет общие справочники и утверждает планы. Назначение этого права не делает пользователя общим администратором портала.
- **Планировщик** получает одну или несколько **групп планов продаж** из классификации номенклатуры (например, `1. RAC`, `2. VRF`, `PROF`). Это не товарные группы и не отдельные группы планирования.

Ответственность ограничивает справочник номенклатуры, доступные группы планирования, состав сценариев, выгрузки, сравнения версий и источники прогноза. Группа планирования со смешанной классификацией доступна, только если все её группы планов продаж назначены планировщику. Сценарий со сторонними группами закрыт целиком, включая архивные строки: частичное редактирование общего JSON-снимка не разрешается. Пустой сценарий планировщика сохраняет назначенную ответственность при создании. Старые пустые сценарии без такой метки доступны администратору.

Персональное назначение имеет приоритет над группами доступа, включая персональное «Нет доступа». При наследовании одной роли «Планировщик» ответственность из нескольких групп доступа объединяется. Конфликт разных проектных ролей требует явного персонального назначения. Пустая ответственность не открывает данные. Общий администратор сохраняет полный доступ.

Планировщик может создавать черновики, менять продажи и распределение, загружать факт и остатки для разрешённых групп, настраивать пары блоков и связи этих групп, выгружать свои сценарии и создавать корректировки. Утверждение, загрузка общих справочников из DataWH и перестроение общего каталога доступны администратору проекта. Источники DDP из модели закупок дополнительно требуют права на проект закупок. При заполнении распределения по истории планировщик использует историю своей группы; общие резервные базы по товарной группе и бренду отключены.

После публикации кода требуется стандартное обновление портала с применением миграции `base.0012_planner_sales_plan_groups`. Затем назначьте роль и ответственность в «Пользователи и роли» или «Группы пользователей». Поля ответственности сохраняются отдельно для пользователя и группы; существующие права остальных проектов не изменяются.
