# Отдельный расчёт для акционеров

В каталоге мотивации, в дополнительных отчётах: **Отчёты для акционеров**.
Один ручной запуск сохраняет пять согласованных представлений: премии команды,
моя премия, детальный расчёт, реестр и обзор для генерального директора без людей.
Показ и Excel используют только сохранённые строки выбранного запуска.

## Источники и правила

- Начальный год — 2026. Дата среза включительна, не позднее сегодня.
- Используется текущий опубликованный подготовленный факт. Это реальные сделки
  до даты, включая исправления, известные на момент запуска, а не реконструкция
  исторического состояния базы. Идентификатор подготовленного набора записан в запуск.
- Параметры плана, квартальная/годовая доли и порог выплаты копируются из задания
  «Все кварталы 2026» при создании; последующее редактирование задания их не меняет.
- Порог авторов по умолчанию 1%. Знаменатель — подписанный чистый оборот физических
  Москвы и ТТ отдельно за выбранные кварталы по дату среза. Формула оборота:
  `Price - AmountUSDIt_ITW + BallsOuterUSD`, с возвратами; только товары и сделки
  с существующим клиентом, как в базовом расчёте.
- Авторы с долей **строго ниже** порога, пустые авторы и авторы с неположительным
  оборотом распределяются на оставшихся пропорционально положительному обороту
  оставшихся. Ровно 1% при пороге 1% остаётся. Между Москвой и ТТ оборот не переносится.
- Части реальных сделок распределяются **до** применения коэффициентов и проверки
  выполнения. Скидка/дата/товар не меняются. Аддитивные денежные поля делятся с точным
  остатком первому получателю. Оборот USD и RUB проверяется до/после; расхождение
  больше 0,01 останавливает публикацию. Если нет базы/получателей, расчёт завершается
  понятной ошибкой, искусственные веса не подставляются.
- Нулевое подразделение без ненулевых оборотов остаётся без перераспределения.
- Для раздельного режима I–III кварталы раздельные, IV и годовая премия объединённые.
  В объединённом режиме Москва и ТТ объединены во всех кварталах (кураторы
  сохраняют физическое подразделение).
- Новые запуски имеют версию `shareholder-original-2026-v2`: I квартал выплачивается
  всегда; II — премия от отгрузок II квартала с проверкой выполнения I–II;
  III — отгрузки и выполнение III; IV — премия от отгрузок IV с выполнением I–IV.
  Годовая премия — сумма годовых долей I–IV с проверкой выполнения I–IV.
  Доли и порог берутся из сохранённых параметров задания.
- Возможная доплата квартала = max(возможная квартальная премия − выплаченная, 0).
  При выполнении годового условия невыплаченные квартальные премии доплачиваются
  при закрытии года; уже выплаченные суммы повторно не начисляются. Годовые доли
  не входят в доплаты. Возможные доплаты не включаются в итог к выплате.
- Годовое условие сохраняется отдельным снимком по автору, продукту и формуле;
  нулевая годовая доля не препятствует доплате. Фильтрация отчёта не меняет условие.
  В Excel всех представлений есть лист «Доплаты и годовая часть» с разделением
  возможной премии, выплаты, годового отчисления, возможной и начисленной доплаты.
  Годовая строка возможных доплат — свёртка кварталов, её нельзя складывать с ними.
- Старые снимки и задания, созданные до обновления, сохраняют предыдущую версию:
  IV и год по IV кварталу, доплаты нулевые. Для новых правил создаётся новый запуск;
  обновление портала само не запускает расчёт и не переписывает снимки.
- «Моя премия» требует одного получателя. Детализация → «Исходные авторы и
  перераспределение сделок» сохраняет первоначальное ФИО, получателя, вес, документ,
  товар, физическое подразделение и оборот каждой части. Excel включает все страницы.
- Фильтры общие для пяти экранов и выгрузок. Они не переопределяют уже рассчитанные
  доли: для другой даты/порога/базы кварталов нужен новый запуск.

## Эксплуатация

Нужна миграция Django `0046_shareholder_calculation`. Обычное обновление портала
применяет её штатно. В Центре расчётов предварительно должно быть установлено
задание «Все кварталы 2026» с текущей подготовкой факта, а для раздельного сценария —
соответствующая `PortalCalcSeparate2026`.

Запуск разрешён администратору. Просмотр — администратору, генеральному директору,
финансисту и роли просмотра мотивации. Роли с персональным/филиальным доступом
сюда не допущены. Планового запуска пока нет.

Веб-процесс создаёт запись и запускает отдельный процесс текущего Python:

```
python manage.py run_shareholder_calculation --run <UUID>
```

Процесс продолжает работу после закрытия браузера. Журнал:
`.local/shareholder-runs/<UUID>.log`. Ошибки соединения не выводятся в интерфейс:
показывается код для поиска в журнале. При остановке самого процесса/сервера
незавершённый запуск не публикуется; создайте новый запуск после устранения причины.

Читается определение уже установленной расчётной процедуры. Заголовок заменяется
локальным пакетом, результатные таблицы и справочник объединения — временными
таблицами одного SQL-сеанса. Неизвестные записи в постоянные таблицы отклоняются.
Исходные `dbo.Sales`, процедуры, рабочие результаты мотивации и расписания не меняются.
Для защиты подготовленного набора удерживается Shared application lock
`PortalMotivationCalculation`. Подготовка и обычный расчёт с Exclusive lock в это
время не запускаются. Два режима рассчитываются последовательно в одном сеансе.
Хеши определений процедур сохраняются вместе с происхождением факта.

Снимки пишутся порциями в базу портала; статус `completed` появляется только после
сохранения всех наборов. Все пять экранов и Excel отказываются читать частичные
снимки. Обычные отчёты продолжают использовать свои прежние источники.

## Проверки

Локальные тесты проверяют пропорции, границу 1%, возвраты, сохранение сумм,
адаптацию SQL обеих реальных цепочек подготовки, запрет постоянных записей,
публикацию снимков, роли, одинаковые суммы пяти экранов и Excel, переходы и фильтры.
Браузерный тест запускается с `RUN_BROWSER_TESTS=1` и Playwright/Chromium.
Выполнение пакета на корпоративном SQL Server необходимо проверить первым
ручным запуском: локальная среда не имеет доступа к `vm-dwh`.

## Архив сохранённых запусков

Администратор может убрать любой запуск из основного списка кнопкой «В архив».
Вкладка «Архив» показывает скрытые запуски и позволяет вернуть их обратно.
Это признак видимости, отдельный от состояния расчёта: архивирование не удаляет
снимки, не останавливает выполняющийся расчёт и сохраняет доступ к отчётам и Excel
по прежним ссылкам. Остальные допущенные роли могут просматривать архив без
возможности менять его. Списки разбиты по 50 запусков на страницу.
Обновление требует миграции `0053_shareholder_archive`; старые запуски остаются
в основном списке, пока администратор сам не перенесёт их в архив.

## Ростов и Питер

Новые запуски с `regional_rule=rostov-piter-policy-plans-2026-v1` дополнительно
включают Д-Ростов и Д-Питер независимо от объединения Москвы/ТТ. Их доли мелких
авторов определяются по полному факту 2026 до даты среза. После перераспределения
доли итоговых авторов определяют их часть каждого товарного плана политиков
каждого периода. Выбранные кварталы отчёта не меняют эти доли. Москва/ТТ сохраняют
свои прежние источники коэффициентов, авторов и выбранных кварталов распределения.

Коэффициенты K0–K4 и формулы политиков регионов копируются из утверждённых версий
портала в параметры нового запуска вместе с датами действия и ревизиями версий.
Снимок содержит также доли плана и применённую матрицу ставок; они доступны в Excel.
При отсутствии точного правила применяется сохранённая формула версии по умолчанию
(«Подразделение(Глобально)»), с сохранением тройной проверки. Числовая ставка и формула —
разные настройки: точные K0–K4 имеют приоритет, числовой резерв остаётся штатным SQL. Неизвестная структура установленной процедуры
также останавливает расчёт для проверки совместимости.

У политиков Ростова и Питера со II квартала действуют **три одновременные проверки**:
общий план-факт подразделения (полная база продаж), общий личный план-факт сотрудника
и план-факт по формуле коэффициента (бренд, товарная группа, группа планов и т. д.).
Даже глобальная формула не отменяет личную проверку. Порог взят из параметров запуска.
I квартал безусловный; II проверяется по I–II, III по III, IV и год по I–IV.
Годовое условие доплат сохраняет те же три проверки, уже выплаченные суммы не повторяются.
Архивные и прежние запуски сохраняют свою прежнюю область подразделений и правила.
