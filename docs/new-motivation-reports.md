# Новая вкладка отчётов мотивации

`/admin_motivationreports-next/` — параллельный пилотный каталог.
Существующие URL, отчёты и сохранённые расчёты не заменяются. Между каталогами
есть вкладки «Текущие отчёты» и «Новые отчёты · пилот».

- Сотрудник: «Моя премия» и подробная расшифровка, с прежним серверным ограничением
  автора, типа и подразделения; ограничения пилота Q4/год сохраняются.
- Директор филиала / заместитель: ведомость доступной команды и детализация,
  с прежними ограничениями подразделений и директорской части заместителя.
- Финансист: реестр рассчитанных премий, детализация, сравнение плановых бюджетов.
- Генеральный директор / администратор: ведомость, детализация и сводный плановый
  бюджет глобальных и локальных коэффициентов. Реестр доступен администратору и
  финансисту.

## Факт

Фактические премии берутся из ReportMotivationByDealAuthor без повторного расчёта
выплат в браузере. Перед чтением проверяется RunId последнего запуска в DWH.
Общая session application lock блокирует параллельную замену таблицы расчётом;
при занятости возвращается сообщение, а не ожидание тяжёлой операции. Lock явно
освобождается. Исторические фактические суммы не архивировались: их нельзя
показывать под датой старого запуска. В селекторе такие запуски для факта отключены.

Ведомость использует отдельную узкую SQL-агрегацию по автору и периоду, без K0–K4,
товарного дерева и второго запроса выполнения подразделения. По 100 строк на
странице; итоги и Excel — по всему отфильтрованному набору. Год совпадает с годом
выбранного запуска. Годовая доплата добавляется один раз отдельным компонентом.
USD и RUB используются из сохранённых полей расчёта, без выдуманного курса.
Из строки передаются расчёт, год, период, подразделение, автор, тип и валюта
в детальный отчёт. Личные права повторно применяются на сервере при каждом чтении
и экспорте, параметры URL не являются разрешением доступа.

## План

Сравнение глобальных и локальных коэффициентов нужно **только по плану**, согласно
уточнению пользователя. По умолчанию выбирается загруженная до запуска копия
плана с той же source_version, что в parameters.plan_version расчёта. Можно явно
выбрать другой загруженный план; фактические премии это не изменяет.

Коэффициенты выбираются по датам из export_snapshot выбранного запуска, включая
уже замещённые версии. Ревизии и сохранённые справочники проверяются; при изменении
истории сравнение отклоняется, а не подменяется текущими ставками. Объединения
подразделений также должны совпадать. Состав директоров берётся из сохранённых
локальных коэффициентов, имена — из экспортного снимка. Глобальный бюджет применён
к каждому из тех же директоров. Две стороны используют одинаковые суммы и O0–O4.

План за квартал — месяцы этого квартала × quarter_share, годовая премия — все месяцы
года × year_share. Все периоды — обе части вместе. Отображаются сумма и процент
разницы локальной премии от глобальной. Политики и продажи имеют план до вида
мотивации: импорт плана не содержит ФИО и не позволяет достоверно распределить
его по сотрудникам. Персональная плановая детализация есть для директоров.

## Реестр и ограничения данных

Согласование коэффициентов не равно согласию на выплату конкретной премии.
Записей согласования выплат и банковских платежей сейчас нет. Реестр поэтому
явно показывает **рассчитанные** суммы для проверки, а не утверждённое платёжное
поручение. Служебные авторы «Политики» выделены как нераспределённые; их нельзя
платить как сотруднику. В источнике автора нет табельного номера, поэтому ФИО
подписано как «сотрудник / автор сделки», без создания фиктивного ID.

Переход на старые отчёты остаётся доступен в любой момент. Новые отчёты не выполняют
SQL-расчёт, выгрузку коэффициентов или изменение решений о выплатах.
