# Планирование продаж Split: интерактивный UX-макет

Открывается администратором портала: **Администрирование → Новые проекты → Открыть макет планирования Split**.
Прямой адрес: `/accounts/administration/sales-planning-preview/`.
`prototype.html` — автономный файл без CDN, внешних шрифтов, библиотек и сетевых запросов.

## Для проверки удобства

1. Канал → объём, коэффициент наценки, DDP. Зелёные поля доступны для ввода; изменения сохраняются локально.
2. «Посмотреть и исправить» → «Указать DDP» для PRIME: открывается панель с фокусом на поле. Для CARBON — исправление сезонности.
3. Открытие группы → месяцы / мощности и модели / DDP и остатки. Доли месяцев отдельные по каналам; мощности общие.
4. Закрепление количества и наценки → изменение итога бренда → предпросмотр → применение. Закреплённые значения сохраняются.
5. «Сток и закупки»: дополнение годовых закупок группой, ожидаемые поступления отдельно, конечный баланс по всем каналам.
6. Прогноз до начала: месячные ручные значения и пример получения части месяца из другого сценария.
7. «Данные и связи»: происхождение данных и предпросмотр демонстрационного обновления без перезаписи ручного ввода.
8. Утверждение блокирует редакторы; новая корректировка сохраняет утверждённый снимок. Предыдущую версию можно сравнить.
9. Excel скачивает реальный файл SpreadsheetML `.xml`, который открывается Excel; это не `.xlsx`.

## Границы макета

Все данные вымышленные. Нет запросов DWH/ERP, серверного сохранения сценариев, реальной выгрузки/утверждения или рабочих прав нового проекта. Просмотр ограничен существующим администратором, пока не спроектированы роли. Кнопка DWH объясняет будущую отправку и не имитирует успешную передачу.

Показаны основные пользовательские пути; редактор справочников, остальные уровни массовой корректировки и импорт прогноза из настоящего сценария предстоит реализовать. Смена режима демонстрирует распределение на год или Q4, не подменяет исторический набор данных. Плановая дата в примере фиксирована.

Числовой движок макета использует JavaScript Number. Производственные расчёты требуют серверных точных десятичных значений и отдельно согласованной точности деления; не переносить демонстрационные формулы как финансовый расчёт. Начальные остатки в таблице — демонстрационные агрегаты. Баланс комплектов не заменяет производственную проверку комплектности двух блоков, которая потребует реальных остатков моделей.

Сброс демоданных: удалить ключ `split-planning-prototype-v1` в localStorage браузера. Обновления и действия макета не затрагивают действующие модули закупок и мотивации.
