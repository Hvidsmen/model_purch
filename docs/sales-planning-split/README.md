# Планирование продаж Split: интерактивный UX-макет

Открывается администратором портала: **Администрирование → Новые проекты → Открыть макет планирования Split**.
Прямой адрес: `/accounts/administration/sales-planning-preview/`.
`prototype.html` — автономный файл без CDN, внешних шрифтов, библиотек и сетевых запросов.

## Для проверки удобства

1. Канал → объём, коэффициент наценки, DDP. Зелёные поля доступны для ввода; изменения сохраняются локально.
2. «Посмотреть и исправить» → «Указать DDP» для PRIME: открывается панель с фокусом на поле. Для CARBON — исправление сезонности.
3. Открытие группы → месяцы / мощности и модели / DDP и остатки. Доли месяцев отдельные по каналам; мощности общие.
4. Закрепление количества и наценки → изменение итога бренда → предпросмотр → применение. Закреплённые значения сохраняются.
5. «Сток и закупки»: дополнение годовых закупок группой, ожидаемые поступления отдельно, конечный баланс по всем каналам.
6. Прогноз до начала: месячные ручные значения и пример получения части месяца из другого сценария.
7. «Данные и связи»: происхождение данных и предпросмотр демонстрационного обновления без перезаписи ручного ввода.
8. Утверждение блокирует редакторы; новая корректировка сохраняет утверждённый снимок. Предыдущую версию можно сравнить.
9. Excel скачивает реальный файл SpreadsheetML `.xml`, который открывается Excel; это не `.xlsx`.

## Границы макета

Все данные вымышленные. Нет запросов DWH/ERP, серверного сохранения сценариев, реальной выгрузки/утверждения или рабочих прав нового проекта. Просмотр ограничен существующим администратором, пока не спроектированы роли. Кнопка DWH объясняет будущую отправку и не имитирует успешную передачу.

Показаны основные пользовательские пути; редактор справочников, остальные уровни массовой корректировки и импорт прогноза из настоящего сценария предстоит реализовать. Смена режима демонстрирует распределение на год или Q4, не подменяет исторический набор данных. Плановая дата в примере фиксирована.

Числовой движок макета использует JavaScript Number. Производственные расчёты требуют серверных точных десятичных значений и отдельно согласованной точности деления; не переносить демонстрационные формулы как финансовый расчёт. Начальные остатки в таблице — демонстрационные агрегаты. Баланс комплектов не заменяет производственную проверку комплектности двух блоков, которая потребует реальных остатков моделей.

Сброс демоданных: удалить ключ `split-planning-prototype-v1` в localStorage браузера. Обновления и действия макета не затрагивают действующие модули закупок и мотивации.

## Рабочий раздел портала

**Модель планирования продаж → Split** доступен через верхнее меню,
«Рабочие разделы» и карточку главной страницы. `/sales-planning/`
перенаправляет на `/sales-planning/split/`.
До определения отдельных ролей доступ сохраняется за активными администраторами
портала, как и для макета; права других проектов не предоставляют доступ.

Рабочая страница отделена от демонстрационного макета. На Split — краткий статус.
В меню «Справочники» находятся загрузка и просмотр каналов продаж и номенклатуры.
Источники — MSSQL, сервер `vm-dwh`, база `DataWH`:
- каналы: уникальные непустые `Даичи_КаналПродаж` из `erp.[Справочники.СтруктураПредприятия]`;
- номенклатура: согласованные девять полей из `erp.[Справочники.Номенклатура]`.
`Ссылка` — устойчивый ключ модели. `Родитель` — название товарной группы.
`Даичи_ГруппаПланирования` и `Даичи_ГруппаПлановПродаж` хранятся отдельно.
`Марка` — бренд, `БИТ_КлассМощности` — мощность,
`БИТ_ТипБлока` — внутренний/наружный, `БИТ_ТипНаружногоБлока` — INV / On-Off.

### Группы планирования — рабочий справочник

«Справочники → Группы планирования», адрес `/sales-planning/directories/groups/`.
Первое формирование выполняется кнопкой из уже загруженной номенклатуры, без DataWH.
После каждой успешной загрузки номенклатуры состав обновляется автоматически в той же транзакции.

Группа определяется непустым `Даичи_ГруппаПланирования`; пробелы по краям и регистр
не создают новые группы. Разные исходные написания сохраняются для точного отбора моделей.
Пустые группы показываются как проблема данных и не образуют фиктивную группу.
Характеристики группы выводятся как набор значений: смешанные бренды или мощности
не заменяются одним произвольно выбранным значением.

Ручные настройки хранятся отдельно: примечание, связанные и замещающие группы,
одна выбранная пара внутренний + наружный блок на каждую мощность.
Выбор ограничен активными моделями той же группы, мощности и соответствующего типа. Тип определяется только по полю «Тип блока» источника; варианты «Внутренний блок» и «БлокВнутренний» распознаются одинаково.
Связи направленные и пока не участвуют в расчётах; планирование сценариев ещё предстоит реализовать.
Обновление номенклатуры не перезаписывает ручные настройки и не подбирает пары автоматически.
Исчезнувшая группа становится неактивной, её ID и настройки сохраняются.
При исчезновении или изменении выбранной модели пара сохраняется с предупреждением.
Новые группы с другим названием не наследуют настройки исчезнувшей группы автоматически.

Доступ к этим страницам и операциям пока только у активного администратора.
Права продукт-менеджеров, источники факта, остатков, поступлений и производственные
формулы сценария не следует считать реализованными по наличию UX-макета.


### Фильтры групп планирования

Список групп поддерживает множественный выбор бренда, товарной группы,
группы планов продаж, мощности, INV / On-Off и статуса настройки пар.
Внутри одного поля значения объединяются через «ИЛИ», между атрибутами — через «И»
по одной и той же активной модели группы. Пустой выбор не ограничивает список.
Поиск названия и включение неактивных групп действуют совместно с фильтрами.
Пагинация сохраняет все повторяющиеся значения. Сброс — ссылка на исходный список.

Статус оценивается по всему текущему составу группы:
- «Настроены»: для каждой мощности есть действительная выбранная пара, проблем классификации нет;
- «Не настроены»: действительных пар пока не хватает либо состав пуст;
- «Требуют проверки»: сохранённая пара устарела или у модели нет мощности/распознанного типа блока.

Фильтр мощности не меняет статус всего состава. Список проблем номенклатуры без группы
учитывает атрибуты, но не статус пар (у такой записи группы ещё нет).
Эти фильтры не меняют состав группы и не записывают настройки.


### Подбор пар по типу блока

В карточке мощности единственный внутренний/наружный кандидат предварительно выбран
по полю «Тип блока». Это не запись в базу: сохранение выполняется POST-кнопкой строки
либо «Сохранить все однозначные пары» для группы. Массовое действие сохраняет только
мощности с ровно одним активным кандидатом каждого типа и без существующей пары.
При неоднозначности или нехватке блока автоматического выбора пары нет.
Ручные и устаревшие сохранённые пары не заменяются: последние требуют проверки.
Для определения типа не используются название модели, мощность, INV / On-Off или цифровые коды.


### Товарная область Split

Рабочая номенклатура и все производные справочники ограничены значением
«Бытовые кондиционеры» в поле «Товарная группа» (источник — Родитель).
Это отдельное утверждённое ограничение состава, а не сравнение названия модели со словом Split.
Фильтр применяется и в SQL загрузки, и при чтении ранее загруженной номенклатуры:
списки, фактические счётчики, группы, фильтры, мощности и кандидаты пар используют одну область.
Карточка группы вне этой области недоступна по прямой ссылке.
Ранее сохранённые записи и ручные связи не удаляются; связи вне области не предлагаются
для нового выбора и сохраняются при редактировании остальных настроек.

После обновления портала область действует на сохранённых данных без повторного импорта.
При следующей загрузке DataWH остальные записи становятся неактивными; пустой или
неуспешный источник не стирает предыдущий успешный снимок.
Каналы продаж общие: согласованный источник каналов не содержит товарной группы.


## Рабочий цикл сценария Split

Меню **Сценарии плана**, адрес `/sales-planning/scenarios/`.
Это серверная реализация ручного цикла, отдельно от исторического UX-макета.
Доступ пока только у действующих администраторов; права иных ролей не добавлены.

### Как пройти цикл

1. Создайте сценарий по четырём обязательным полям: название, дата начала планирования,
   дата окончания планирования и дата фактического стока. Конец не привязан к 31 декабря;
   год определяется из начала. Дата стока не позже начала. Автоматической подстановки даты стока нет.
2. В созданном черновике на вкладке «План продаж» выберите группы, каналы и способ
   задания объёма, подтвердите состав и нажмите «Начать планирование».
   Затем заполните объёмы, DDP комплекта и коэффициенты наценки.
   При годовой цели заполните состоявшийся факт до начала: план = цель − факт.
   Цена DDP общая по каналам, наценка отдельная; есть закрепления от массовой правки.
3. Распределите месяцы в процентах либо прямо в комплектах. Месячные количества
   должны совпадать с объёмом группы/канала; проценты — составлять 100%.
   Равномерное распределение запускается только явной кнопкой пользователя.
4. Задайте доли мощностей (общие для каналов), пары блоков, соотношение стоимости
   мощностей и процент стоимости внутреннего блока. Внешние фактические доли и
   стоимости пока не подключены и не подменяются демонстрационными значениями.
5. Заполните по мощностям остатки обоих блоков на дату снимка, поступления до начала
   и в плановом периоде, дополнительные закупки в комплектах. При разрыве дат —
   месячный прогноз продаж до начала плана, по всем каналам.
6. Откройте детальный расчёт по моделям и проверки. Исправьте блокирующие ошибки.
   Дефицит на конец — предупреждение, утверждается только с явным подтверждением.
7. Утвердите версию. Редактирование заблокируется на сервере. Создайте корректировку
   для новых изменений, сравните версии, скачайте Excel или CSV детализации.

### Правила вычислений

Денежные и количественные значения рассчитываются через Decimal, без float.
Ввод и распределения поддерживают до 6 знаков после запятой; финансовые суммы
в интерфейсе показаны с двумя знаками. Остаток округления распределения получает
последняя положительная доля, нулевая доля его не получает.
Стоимость и выручка распределяются по фактически распределённым количествам,
затем по относительной стоимости мощностей и доле стоимости двух блоков.
Итоги количества, DDP и выручки сохраняются; два блока не складываются в комплекты.
Сток вычитает тот же план моделей, который показан в детальном расчёте.
Комплекты на конец — сумма минимумов остатков внутреннего и наружного блока
по каждой мощности. Внутримесячный дефицит не моделируется.

Пустое поле внешнего источника не считается нулём. Нулевые остатки/поступления
подтверждаются ручным нулём. Дополнительные закупки — отдельный ручной план (начально 0).
Массовая правка бренда сначала показывает предпросмотр. Закрепления сохраняются;
нет исходных пропорций, несовместимые закрепления или недостижимый до цента итог
при точности наценки 6 знаков — ошибка, а не скрытое перераспределение.

### Прогноз, состав и история

Прогноз можно перенести из утверждённого сценария с совпадающими группами:
все каналы суммируются, количество берётся по одному типу блока. Часть месяца
распределяется равномерно по календарным дням планового интервала источника.
Есть предпросмотр. Применение заменяет прогноз выбранных месяцев вкладом выбранного
интервала; происхождение сохраняется. Неполное покрытие нужного месяца блокирует
утверждение до ручного дополнения и сохранения полного месячного прогноза.

Каждая версия хранит снимок названий, кандидатов моделей, выбранных пар и данных,
поэтому последующее редактирование справочников не меняет утверждённый план.
В черновике можно явно обновить снимок состава: ручные значения сохраняются,
исчезнувшие модели/мощности требуют проверки. Замещающие и связанные группы
сохраняются в снимке; автоматическое суммирование их складских источников пока
не подключено — остатки с учётом замен задаются вручную.

Группы и каналы можно добавлять/исключать в черновике. Исключённый ввод остаётся
в архиве состояния и восстанавливается при повторном добавлении; в итогах он не участвует.
Запись проверяет ревизию: старая вкладка не перезаписывает свежие изменения.
Все изменения и утверждения имеют серверную историю автора, времени и ревизии.
У семьи сценария одна текущая корректировка, утверждённые версии не перезаписываются.

### Подключения, оставленные на следующий этап

Факт продаж/исторические доли, остатки, ожидаемые поступления и отправка в DataWH
пока **не подключены**. Их состояние явно показано на вкладке «Данные и связи».
Ручной цикл работает без них. Excel — настоящий .xlsx с итогами, проверками,
остатками и распределением до моделей. CSV утверждённой версии — реальная
детализация для будущего согласования схемы DWH, а не выполненная отправка в SQL Server.
Новых производственных Python-зависимостей нет: openpyxl уже включён в requirements.
Миграция base/0010 создаёт таблицы сценариев и истории; существующие справочники не перестраиваются.


### Этап создания и этап планирования

Форма создания не содержит года, режима «новый год/остаток года», групп, каналов
или способа ввода объёма. Новый сценарий сохраняется без состава; все вкладки
такого черновика открываются, но утверждение пустого плана блокируется.
Выбор состава и способа ввода находится на вкладке «План продаж», включая последующие
изменения состава. Старые сценарии, утверждённые версии и их даты не переписываются.
Начало и конец могут находиться в разных годах; распределение охватывает фактический
интервал. Дата стока обязательна и не должна быть позже начала планирования.


### Матрица плана и изменение состава

Основная таблица: группы планирования по строкам, каналы продаж — группами столбцов.
DDP комплекта общий, а план/годовая цель, состоявшийся факт и коэффициент наценки
находятся под заголовком соответствующего канала. Закрепления количества и наценки
остаются рядом с вводом в каждой ячейке.

Над таблицей доступны «Добавить группу» и «Добавить канал», в заголовках — исключение
группы/канала из плана. Это не удаление записи из справочника. Текущий ввод таблицы
сохраняется атомарно вместе с изменением состава, с проверкой ревизии.
Исключённые данные архивируются и восстанавливаются при повторном добавлении.
Допускается убрать последний канал или группу: черновик остаётся доступным,
но пустой состав не может быть утверждён. У утверждённой версии операции запрещены.


### Добавить группы из стока и товара в пути

Над матрицей есть действие «Добавить из стока и в пути». Источник присутствия —
уже используемая в проекте таблица `DataWH.erp.StreamGoods`, сервер `vm-dwh`.
Берётся срез строго на дату фактического стока сценария, все склады.
Номенклатура соединяется по ссылке, ограничивается товарной группой
«Бытовые кондиционеры». Модель учитывается, если суммарное ВНаличии > 0
либо ВПути > 0; группы дедуплицируются. КПоступлению и правила ожидаемых
дат закупочного модуля здесь не подменяют ВПути.

Действие добавляет только состав групп; каналы не выбираются автоматически,
плановые количества, наценки, DDP, доли и ручной сток не заполняются источником.
Текущий ввод матрицы сохраняется вместе с добавлением в одной операции.
Уже выбранные группы не перезаписываются, архивные настройки возвращаются.
Дата, момент проверки, источник и признаки «в наличии/в пути» сохраняются в состоянии.

Отсутствующий срез не считается нулевым стоком. Если по данным источника группа
не найдена в активном справочнике, требуется обновление номенклатуры и групп:
частичное добавление не выполняется. Ошибка подключения также не меняет сценарий.
Это первое подключение для подбора состава, а не загрузчик количественного стока
или выполненная синхронизация остальных источников. Рабочий запрос требует проверки
на сервере; автоматические тесты используют контролируемые ответы DataWH.


### Поиск при добавлении группы и канала

Списки добавления группы и канала над матрицей содержат поиск по подстроке без учёта
регистра, «Нет совпадений» для пустого результата и управление Enter/стрелкой/Escape.
Сохраняется обычное значение native select, поэтому отправка формы и backend не меняются.
Меню находится поверх области прокрутки таблицы и вписывается в окно; утверждённые
сценарии остаются только для чтения. Без JS доступны исходные стандартные списки.
