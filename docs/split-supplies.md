# Запланированные и новые поставки

В таблице стока показаны две колонки поставок:

- **Запланировано в периоде** — поступления внутри планового периода из
  сохранённой загрузки `DataWH.erp.StreamGoods`. По умолчанию комплекты;
  при раскрытии — внутренние и наружные блоки. SQL-база не редактируется
  формой, а обновляется кнопкой загрузки остатков и приходов.
- **Новые поставки** — ручной объём в комплектах. Использует существующее
  поле дополнительных закупок `buy`, поэтому прежние значения сохраняются
  и не учитываются второй раз.


Новые поставки распределяются по сохранённым долям мощностей.
Ненулевой объём требует заполненных долей с суммой 100%.

Колонка корректировки убрана из таблицы. Ранее сохранённые корректировки
не сбрасываются и продолжают учитываться в расчёте и Excel; изменение
оформления не переписывает снимки запусков. Сохранённая корректировка
изменяет оба типа блоков на одинаковое количество комплектов по мощности.
Она не может уменьшить ни один тип блоков ниже нуля. Для ненулевой
корректировки количество обоих компонентов должно быть известно.

Остаток рассчитывается по каждой мощности и каждому типу блока:

`сток на начало + SQL-поставки + корректировка + новые поставки − продажи`.

Комплекты на конец — минимум двух типов блоков по мощности, затем сумма
по мощностям. Исходные количества, новые поставки и корректировка показаны
также в Excel. Поступления до начала плана остаются отдельной колонкой
и входят в сток на начало, повторно здесь не прибавляются.

Повторная SQL-загрузка заменяет только базу поставок; новые поставки и
корректировка сохраняются. Если новая база стала меньше отрицательной
корректировки, расчёт показывает ошибку до исправления корректировки.

Для старых снимков без выделенной SQL-базы используются прежние сохранённые
поступления. Чтобы получить подтверждённую SQL-базу и защитить её от ручной
замены, нужно обновить остатки и приходы. Отдельной миграции БД не требуется.
