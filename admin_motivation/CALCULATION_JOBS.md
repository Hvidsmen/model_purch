# Запуск расчёта мотивации из портала

После обновления выполните миграции (`python manage.py migrate`) и перезапустите сервер.
Администратору доступен пункт «Слияние подразделений» в боковом меню портала;
«Расчёт и задания» доступен также со страницы слияния.

## Расчёт и расписания

1. Создайте задание: только вручную, ежедневно или однократно. Время вводится по Москве.
2. Нажмите «Запустить сейчас» для ручного запуска. Запрос возвращается после передачи задания SQL Server Agent; это не означает завершение расчёта.
3. Обновите статусы: отображаются фактическое выполнение и последний результат SQL Agent. Подробности ошибки доступны в истории задания SQL Server Agent.
4. Для остановки расписания снимите «Расписание включено» и сохраните. Ручной запуск остаётся доступен.

Нужны DWH_SQL_CONN_STR, доступ к DataWH, запущенный SQL Server Agent, права на собственные задания msdb, VIEW DEFINITION исходной процедуры и создание объектов в схеме motivation.
Портал создаёт управляемую копию `motivation.PortalCalcBySub` из текущей `motivation.sp_CalcBySub`. Оригинал не изменяется. Новая копия подготавливается при сохранении/запуске задания.
Расписания хранятся в SQL Server Agent и не зависят от процесса веб-сервера. Время переводится в часовой пояс SQL-сервера по его текущему смещению UTC; для серверов с сезонным переводом часов расписание следует пересохранить после смены смещения.
Одновременные запуски из портала блокируются общей блокировкой SQL Server. Прямой запуск исходной процедуры вне портала эту блокировку не использует.

## Объединение подразделений

Отметьте одно или несколько присоединяемых подразделений в списке с поиском, выберите получателя, последнюю редактируемую версию и приоритет коэффициентов. Сначала просмотрите конфликты, затем подтвердите объединение. Например, источник «Термотрейд», получатель «Д-Москва».
В текущей версии коэффициенты переносятся получателю, директоры привязываются к получателю.
Привязки групп доступа и личных отчётов также переносятся на получателя,
без изменения точных ФИО авторов сделок. Если группа включала оба подразделения,
в ней остаётся один получатель. Состав затронутых групп и личных привязок
показывается до выполнения и записывается в историю. Архивные строки и исходные строки планов не переписываются; при чтении и расчёте используется соответствие названий. Несогласованные расчёты планов сбрасываются и должны быть пересчитаны. Утверждённые результаты не сбрасываются.
К одному получателю можно присоединить несколько подразделений за одно подтверждение
или добавить новые подразделения позже. Получателя нельзя одновременно отметить
источником. Присоединение уже объединённой группы в другую группу не поддерживается:
все соответствия должны вести непосредственно к итоговому подразделению.

Приоритет задаётся для итогового подразделения либо для одного явно выбранного
присоединяемого. Если у приоритетного подразделения нет коэффициента для конкретной
классификации, используется коэффициент получателя, затем первый доступный среди
остальных источников по алфавиту. Порядок показан в предпросмотре. Конфликты между
источниками учитываются, даже если у получателя для классификации нет строки.
Исторические коэффициенты при чтении разрешаются в том же порядке, независимо от
порядка строк запроса. При присоединении к существующей группе правило приоритета
обновляется для всей группы; прежние правила сохраняются в деталях журнала.

Всё подтверждённое слияние выполняется одной транзакцией: перенос коэффициентов,
доступа и директоров, правила названий и журнал либо сохраняются целиком, либо
откатываются при ошибке. Подписанный предпросмотр привязан ко всему набору источников,
получателю, версии и приоритету. Изменения коэффициентов или состава правил после
предпросмотра требуют повторной проверки. Перед SQL-расчётом необходимо заново
синхронизировать все соответствия группы.

Для SQL-расчёта сначала утвердите нужную версию коэффициентов, затем нажмите «Синхронизировать с SQL Server» на странице объединения. Сопоставление названий, утверждённые коэффициенты и подготовленная процедура записываются одной SQL-транзакцией. При ошибке изменения SQL откатываются; локальное объединение остаётся и синхронизацию можно повторить.
Запускайте расчёт через портал или `motivation.PortalCalcBySub`: исходная процедура напрямую не учитывает сопоставление портала.

Автоматические тесты используют имитацию SQL Server; доступность службы Agent и права реальной учётной записи проверяются при первом сохранении задания. Эти тесты не выполняют расчёт в рабочем DWH.


Предварительный просмотр подписывается на 30 минут и привязывается к паре
подразделений, версии, приоритету и текущим коэффициентам/привязкам. Изменение
этих данных требует повторной проверки. Подтверждение без просмотра не принимается.
На странице есть быстрый выбор «Термотрейд → Д-Москва», выбор остальных
подразделений выполняется теми же полями. Слияние постоянное; правило пилота
«выполнение по подразделению, выплата за личный объём» — отдельная настройка расчёта.
