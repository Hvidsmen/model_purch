# Запуск расчёта мотивации из портала

После обновления выполните миграции (`python manage.py migrate`) и перезапустите сервер.
Администратору доступны пункты «Расчёт и задания» и «Объединить подразделения» в меню мотивации.

## Расчёт и расписания

1. Создайте задание: только вручную, ежедневно или однократно. Время вводится по Москве.
2. Нажмите «Запустить сейчас» для ручного запуска. Запрос возвращается после передачи задания SQL Server Agent; это не означает завершение расчёта.
3. Обновите статусы: отображаются фактическое выполнение и последний результат SQL Agent. Подробности ошибки доступны в истории задания SQL Server Agent.
4. Для остановки расписания снимите «Расписание включено» и сохраните. Ручной запуск остаётся доступен.

Нужны DWH_SQL_CONN_STR, доступ к DataWH, запущенный SQL Server Agent, права на собственные задания msdb, VIEW DEFINITION исходной процедуры и создание объектов в схеме motivation.
Портал создаёт управляемую копию `motivation.PortalCalcBySub` из текущей `motivation.sp_CalcBySub`. Оригинал не изменяется. Новая копия подготавливается при сохранении/запуске задания.
Расписания хранятся в SQL Server Agent и не зависят от процесса веб-сервера. Время переводится в часовой пояс SQL-сервера по его текущему смещению UTC; для серверов с сезонным переводом часов расписание следует пересохранить после смены смещения.
Одновременные запуски из портала блокируются общей блокировкой SQL Server. Прямой запуск исходной процедуры вне портала эту блокировку не использует.

## Объединение подразделений

Выберите источник, получателя, последнюю редактируемую версию и приоритет коэффициентов. Сначала просмотрите конфликты, затем подтвердите объединение. Например, источник «Термотрейд», получатель «Д-Москва».
В текущей версии коэффициенты переносятся получателю, директоры привязываются к получателю. Архивные строки и исходные строки планов не переписываются; при чтении и расчёте используется соответствие названий. Несогласованные расчёты планов сбрасываются и должны быть пересчитаны. Утверждённые результаты не сбрасываются.
Повторное объединение уже объединённых групп не поддерживается.

Для SQL-расчёта сначала утвердите нужную версию коэффициентов, затем нажмите «Синхронизировать с SQL Server» на странице объединения. Сопоставление названий, утверждённые коэффициенты и подготовленная процедура записываются одной SQL-транзакцией. При ошибке изменения SQL откатываются; локальное объединение остаётся и синхронизацию можно повторить.
Запускайте расчёт через портал или `motivation.PortalCalcBySub`: исходная процедура напрямую не учитывает сопоставление портала.

Автоматические тесты используют имитацию SQL Server; доступность службы Agent и права реальной учётной записи проверяются при первом сохранении задания. Эти тесты не выполняют расчёт в рабочем DWH.
