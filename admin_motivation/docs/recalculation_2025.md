# Пересчёт 2025

В разделе «Отчёты» добавлен отдельный пункт «Пересчёт 2025» с вкладками
«Политики» и «Продажи». Выгрузка USD содержит четыре листа: «1. Политики», «2. Продажи»,
«3. Выполнение политик», «4. Выполнение продаж».
Колонки: подразделение, сотрудник (только политики), I квартал, II квартал
(проверка I–II), III квартал, IV квартал (проверка I–IV), годовая премия,
**доплаты за кварталы**, итог. Доплаты не смешиваются с годовой премией;
итог включает обе суммы ровно один раз. Есть итоги подразделений и общий итог.
Кадровый справочник и отдельное подразделение сотрудника не используются.

## Входные данные

Факт и план — за 2025 год. Подразделения берутся из исходных данных DWH, без
портального объединения Москвы и ТТ и без ограничения только московским расчётом.
Обычные самостоятельные исключения подразделений исходного расчёта сохраняются;
снято именно ограничение **канала ДПП для продаж**. HEAT для продаж включён.
Для политик HEAT и канал ДПП исключены. Директора в новый отчёт не добавляются,
их ставки и результаты существующих расчётов не заменяются.

Согласованный файл соeffs.xlsx загружается через закрытую форму портала.
Сами ставки не включены в исходный код и публичный репозиторий.
Проценты Excel хранятся как дроби, без повторного деления/умножения на 100;
ставки нормализуются до шести знаков дроби. Формулы, дубли и неполные ставки
отклоняются. Настройки сохраняются в отдельном Motivation2025Input с заданием,
именем и хешем файла; действующие версии коэффициентов не экспортируются.

План политиков распределяется по факту 2025 года для каждой пары
«подразделение документа + товарное сочетание коэффициентов»:

`план политика = план сочетания × факт политика / общий факт сочетания`.

Товарные ключи — группа планов продаж, группа ERP и бренд. `*` соответствует
обобщённому сочетанию. Более конкретная группа/бренд имеет приоритет; OUTER APPLY
выбирает один набор ставок, не размножая сделку. Эти же ключи используются для
долей плана. Москва и ТТ распределяются отдельно. Суммируется факт всего 2025 года,
а не прошлого года или отдельного квартала. Строки без автора показываются как
«Не заполнено». Когда документ не найден при обогащении рабочей копии Sales,
уже заполненный автор Sales не стирается.

## Запуск и проверка

1. Обновить портал и применить миграцию 0035.
2. В «Отчёты → Пересчёт 2025» выбрать загруженный план 2025 года, сохранить
   согласованный файл коэффициентов. Стандартные доли 80/20,
   порог 0,8; параметры видны перед запуском.
3. Нажать «Запустить пересчёт 2025». Запуск доступен администратору, только вручную.
   При повторном нажатии выполняющееся задание не дублируется.
4. После завершения открыть вкладки и скачать Excel с четырьмя листами.

Используется отдельная `motivation.PortalCalcTest2025`, собранная из версионируемого
шаблона `sql/templates/recalculation_2025.sql.in`. За основу взят рассмотренный
полный квартальный/годовой расчёт. Действующая `sp_CalcBySub` не читается и не
изменяется: её нынешние директора и переходные правила не блокируют 2025 год. Итоги пишутся
в `FactTest2025`, `PlanFactTest2025`, `ReportMotivationByDealAuthorTest2025`.
Расчёт обогащает частную временную копию Sales. Общие Fact/PlanFact/Report и Sales
не заменяются. Новые ставки передаются параметром JSON в SQL Agent; точные
формулы и сегменты скидок остаются датированными настройками DWH. База мотивации
сохраняет `Price − AmountUSDIt_ITW + BallsOuterUSD`. Переходные окна 2026 не
применяются, четыре квартала и годовая доплата исходного расчёта сохраняются.

Проверяются год плана, покрытие ставок, отсутствие повторных товарных ключей и
возможность распределить план по факту. При нулевом знаменателе или отсутствии
факта для ненулевого плана запуск завершается ошибкой, без подстановки полного
плана каждому сотруднику. Проверяется собственный шаблон SQL до установки процедуры/задания. В нём
заданы @FactYear, @PlanVersion, @QuarterShare, @YearShare; портал добавляет
порог и снимок ставок. Для установки нужны права создания/изменения своей
процедуры, выходных таблиц и SQL Agent. VIEW DEFINITION на действующую
sp_CalcBySub больше не требуется.

Перед чтением берётся общая блокировка расчёта. Проверяются последний успешный
запуск, вариант, ключ задания, версия правил, хеш коэффициентов и параметры.
Результат другого/неуспешного запуска не показывается как новый.

## Общее изменение продаж

Для всех портальных расчётов продаж канал ДПП и HEAT участвуют в премиальной
базе. Политики и директора этим изменением не переключаются. Представление
выполнения плана использует те же исключения. Правило перехода 2026 получило
новую версию: уже сохранённые результаты требуют пересчёта для нового правила.

## Проверки

Тесты покрывают импорт, финансовые итоги и отдельные доплаты, ключи распределения,
сохранение общего плана, изоляцию SQL и Sales, параметры/год/хеш, доступ и Excel.
Браузерный тест проверяет вкладки и фактическое скачивание четырёх листов с
контрольными суммами. В среде разработки нет подключения к vm-dwh: выполнение
SQL Server и сверка реальных сумм 2025 выполняются на сервере портала.

## Листы выполнения плана

Третий и четвёртый листы содержат подразделение, сотрудника (политики),
товарное сочетание, формулу, период, план и факт проверки, процент выполнения,
порог задания, дополнительные проценты подразделения и сотрудника, начисление,
выплату, доплаты, итог и пояснение. Это детализация условий выплаты, а не новые
начисления. Итоги первых двух листов не меняются.

Оконные план/факт из сохранённого отчёта не суммируются повторно: используется
значение окна для сочетания формулы и товара. Годовые строки доплат с нулевыми
входами не стирают ненулевое/отрицательное окно. Для I квартала используются
физические отгрузки, план мотивации равен факту; порог не применяется. Нулевой
или отрицательный знаменатель не выдаётся за 0% — процент остаётся пустым.

Дополнительные условия личных формул берутся из PlanFactTest2025 того же
запуска. Сначала воспроизводится группировка #pf_base, затем подстановка
единицы вместо нулевого плана в исторических личных условиях. Для глобальной
формулы личный порог не применяется, используется настоящий план подразделения.
Периоды: I — первый квартал, II — I–II, III — третий, IV/год — весь 2025 год.
Общие проценты повторяются у товарных сочетаний и не суммируются в общий итог.

Пояснение указывает обнаруженные невыполненные условия. Если проценты не
объясняют нулевую выплату, лист предлагает проверить ставки/корректировки,
не приписывая ноль невыполнению плана. Новых запросов при обычном просмотре
вкладок нет: диагностика читается только при экспорте, под той же блокировкой
и после проверки идентичности успешного запуска. Пересчёт для добавления
листов не требуется.

## Сохранение и повторный запуск

Форма загрузки связывается с POST только для действия «Сохранить». Нажатие
«Запустить» не валидирует пустые поля другого HTML-form. При открытии и после
неудачного запуска поля заполняются сохранённым планом, долями и порогом.
При изменении параметров новый файл необязателен: ранее сохранённый снимок
коэффициентов копируется в новое задание, старое задание не меняется.

Ошибка подготовки/запуска сохраняется в job.error и остаётся видна после
обновления страницы. Статус явно отличает «входные данные сохранены» от
успешного старта и готового результата. POST запуска заканчивается редиректом,
поэтому обновление страницы не запускает SQL повторно. При успешной повторной
попытке ошибка очищается. URL фиксирует идентификатор выбранного задания,
чтобы новое сохранение в другом окне не подменяло показанные параметры.

Шаблон 2025 — самостоятельный текст без SSMS-директив GO и исполняется только
после подстановки имени отдельной процедуры, изоляции Sales/выходных таблиц
и настройки ставок. Текущие функции/назначения директоров не переносятся.
Формулы и пороги скидок по датам продолжают читаться из настроек DWH.
