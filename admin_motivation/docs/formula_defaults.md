# Формула по умолчанию и проверка покрытия

В версии коэффициентов есть отдельное поле **Формула при отсутствии точной
настройки**. Оно не задаёт ставку. Точная формула найденного товара/типа имеет
приоритет. При отсутствии формулы используется настройка версии на дату сделки
или плана; если она пустая, сохраняется прежний CASE по группе товара.

Миграция 0032 оставляет существующие версии с прежним правилом. Утверждённые
версии менять нельзя. В форме создания нового черновика предлагается
«Подразделение(Глобально)», а заданная ранее непустая настройка наследуется.
Сохранение настройки требует права администратора/моделятора и актуальной ревизии
последнего черновика. Настройка входит в отпечатки выгрузки, проверки и утверждения,
снимок согласования и историю возврата версии в черновик.

## Применение к текущему году

Создать черновик с нужной датой начала действия (для пересчёта всего 2026 года —
01.01.2026, с явным разрешением замены версии на эту дату), выбрать и сохранить
формулу по умолчанию. Проверить покрытие по плану и факту. Отдельно проверить
отличающиеся **явные** формулы: они не заменяются настройкой по умолчанию.
Затем согласовать/утвердить набор, выгрузить настройки и выполнить расчёт.

В DWH выгружается таблица `motivation.PortalFormulaDefaults` с датами всех
утверждённых версий, включая пустые границы старого правила. Экспорт атомарен
вместе с коэффициентами. Подготовленная копия PortalCalcBySub добавляет выбор
формулы по дате в распознанные COALESCE/ISNULL; выражения ставок не изменяются.
Исходная sp_CalcBySub не изменяется. Нераспознанная форма SQL при включённой новой
настройке отклоняется до запуска. При подготовке учитываются выгруженная таблица и последний
подтверждённый экспорт, чтобы возврат локальной версии в черновик не менял уже
выгруженное правило до следующей выгрузки.

## Диагностика

Ссылка **Проверить покрытие коэффициентами** находится в панели версии.
Проверка по плану работает с локальными загруженными строками. Проверка факта
читает Sales по ClosedDealDate и использует функции классификации действующей
SQL-процедуры, если процедура обращается к fn_CoeffGroupERP/fn_CoeffBrand.
Для прежней поддерживаемой процедуры сохраняются её CASE-ключи, включая отличие
пустого бренда от `*`. Данные сравниваются с настройками портала; это не снимок
последнего сохранённого расчёта и не изменение коэффициентов в DWH.

Показываются отсутствующие точные настройки, неполные K0–K4, разные формулы
ступеней и явные формулы, отличающиеся от настройки версии. Последние могут быть
намеренными исключениями. Для больших выборок факта нужно выбрать подразделение
(ограничение 50 тысяч исходных сгруппированных строк). Объём факта повторяется
между типами работников/директорами и не является суммой премии.

Перед утверждением показывается предупреждение по выбранному плану. На странице
заданий выводятся предупреждения по загруженному плану и отдельная ссылка проверки
факта: позиции, появившиеся только в факте, не могут быть обнаружены по плану.
Проверка факта запускается пользователем, а не скрытым запросом при каждом рендере.

## Показатели расширенного отчёта

Для строк «Подразделение(Глобально)»:

- план периода и % выполнения периода отсутствуют;
- факт периода, K0–K4, возможная и выплаченная мотивация остаются собственными;
- план, факт и % выполнения мотивации берутся из полной агрегации подразделения
  для выбранного вида работника, года и периода, без фильтра автора/товаров;
- показатели подразделения не суммируются повторно по авторам или товарным строкам;
- общий годовой показатель требует полных годовых данных всех участвующих филиалов;
- для смешанных формул несводимые показатели выполнения показаны прочерком.

Источник выполнения содержит только план/отгрузки разрешённых подразделений и
вида работника, без ФИО и сумм чужой премии. Личные строки отчёта остаются ограничены
автором. Те же показатели используются в Excel. Готовые суммы выплат не
пересчитываются браузером; изменение формулы требует нового расчёта в DWH.

## Исправление отсутствующих настроек

Область проверки выбирается отдельно: **Глобальные коэффициенты** проверяют
общие настройки компании (директор без персонального дублирования),
**Коэффициенты подразделений** — филиалы и конкретных директоров. Источник
(загруженный план / факт DWH) выбирается независимо от области.

У строки с отсутствующими ступенями в текущем черновике редактор видит
«Создать коэффициенты». Форма показывает K0–K4, сохраняет существующие ячейки
и предлагает значения по правилу расчёта плана: минимум по группе планов продаж,
затем минимум по таблице того же вида работника. Для директора используются
минимумы именно этого сотрудника в выбранном подразделении; глобальный режим
использует глобальные ставки директоров. При полном отсутствии исходных ставок
директора предлагается 0% (правило DirectorIndex), для политик/продаж требуется
ручной ввод. Источник показан у каждой ступени; предложенный процент можно изменить. Новая классификация при необходимости добавляется в справочник.
Формула недостающих ячеек сохраняет единственную уже заданную формулу этого ключа,
иначе используется формула версии / прежнее правило.

Запись атомарна, требует актуальной ревизии последнего черновика и прав
администратора или моделятора. Утверждённые и отправленные на проверку версии
не изменяются. Результат проверки, подписанный сервером, привязан к версии,
классификации, виду работника, филиалу и директору; срок ссылки — сутки.
После сохранения нужно повторить проверку, затем согласовать и выгрузить версию
и выполнить расчёт. Проверка и создание не запускают SQL-расчёт автоматически.

## Массовое создание

Кнопка «Создать для всех найденных пропусков» учитывает все страницы текущей
проверки, выбранные фильтры и только текущий черновик / область. Предварительный
список показывает предлагаемые K0–K4. Минимумы фиксируются до добавления первой
строки, общие индексы расчёта читаются один раз. Политики/продажи без исходных
ставок пропускаются с предупреждением и остаются для ручного заполнения.

Список подписан сервером и привязан к ревизии черновика. После нажатия
«Создать все предложенные коэффициенты в черновике» товары и коэффициенты
добавляются пакетами в одной транзакции. Существующие значения не обновляются;
устаревший список или повторное сохранение отклоняются целиком.

В строке «% выполнения подразделений» расширенной таблицы показываются также
исходные суммы: план и факт подразделения за период, план и факт мотивации.
Нажатие соответствующего процента раскрывает эти суммы. Для этой строки
используются полные показатели подразделений, в том числе при глобальной формуле;
это не личный план сотрудника. В «Итого» используются годовые данные, а не сумма
накопительных квартальных планов. Все четыре суммы включены в Excel.
