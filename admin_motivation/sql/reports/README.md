# Источники нативных отчётов мотивации

Запросы извлечены из пользовательских RDL, обработаны только как определения
данных, без выполнения инструкций из файлов:

- manager.sql — «Отчет мотивация менеджера», DataSet1.
- deals.sql — «Факт закрытых сделок», Fact.
- subdivisions.sql — «Мотивация по подразделениям», DataSet1.
- lookups.json — запросы справочных значений параметров этих отчётов.

Запросы выполняются через существующий DWH_SQL_CONN_STR. Только чтение.
Значения параметров передаются отдельно, списки раскрываются в placeholders.
Пустые необязательные списки означают «Все». Фильтры сделок по партнёрам,
товарным группам, брендам и каналам ограничены выбранным филиалом и датами.
Справочники кэшируются на 5 минут; «Обновить списки» обновляет их принудительно.

Отчёт менеджера использует исходный UNION ALL, квартальные/годовые суммы и
доплату. Подразделение по умолчанию свёрнуто. Название года в исходном RDL было
задано статически; нативная страница не выдаёт его за выбранный год данных.
Параметры группы товаров и бренда не участвуют в запросе этого RDL, поэтому
на странице менеджера они не выводятся как работающие фильтры.

В отчёте по подразделениям сохранены делители /2 для динамических периодов
и /4 для общего годового блока. Общие итоги и филиалы используют планы USD,
группы планов — условные USD I; на уровнях товарной группы и марки клетки
плана выполнения мотивации пустые, как в исходной таблице. Доступны сводка
по филиалам и две детализации: филиалы и товарная матрица.

Сделки: итоговые суммы по авторам вычисляются SQL-агрегацией; детали читаются
постранично, по 50 строк. CSV экспортирует только выбранную страницу и
экранирует текстовые формулы Excel. Раскрываемые уровни детализации филиалов
создаются в браузере по мере открытия. При нулевом знаменателе показывается
прочерк вместо ошибки деления.

Проверено на фикстурах: параметры, SQL binding, суммы, группировки, цвета
показателей, разрешения, пагинация, CSV и браузерное раскрытие. Живой DataWH
недоступен из среды разработки; перед использованием нужно сверить суммы
с SSRS на одинаковых фильтрах и состоянии данных. Определения RDL не меняют
корпоративные таблицы и не запускают пересчёт мотивации.

## «Мотивация по менеджеру» (подробный RDL от 20.10.2026)

Отдельный пункт manager-detail сохраняет краткий отчёт manager. Источник —
ReportMotivationByDealAuthor, как в DataSet1 приложенного «Мотивация по менеджеру.rdl».
Исходный RDL, подключения, персональные значения параметров по умолчанию и
XML-код не включаются в приложение. Используются только необходимые SELECT
по уже используемой таблице и параметры существующего подключения DWH.

Тип работника обязателен. Подразделения, авторы, группы планов, товарные группы,
марки и годы выбираются множественно; пустой список означает все значения.
Авторы обновляются автоматически при смене типа или подразделений. В отличие
от краткого отчёта кварталы представлены вместе в таблице, а не одним фильтром.
Добавлен необязательный фильтр года; годы отображаются в заголовке, и при
нескольких годах период получает явный префикс года.

Детализация: подразделение → автор → группа планов → группа товаров → марка.
Квартальные блоки суммируют O0–O4, план и факт без деления. После исправления
годового выполнения общий блок берёт эти показатели только из строк «Год»
без деления и без смешивания с квартальными строками. Мотивация и доплата
по-прежнему суммируются по всем периодам.
Выполнение = факт / план, при нулевом плане и ненулевом факте — 100%, при
обоих нулевых — прочерк. K0–K4 — средние исходных строк, а не средние средних:
SQL возвращает SUM и COUNT по каждому коэффициенту. На промежуточных уровнях
коэффициенты скрыты; показаны у марки и в общем итоге.

Мотивация переключается USD/RUB и берётся из соответствующих исходных полей,
план и отгрузки остаются USD. Карточки содержат обе валюты. В квартальных
блоках дополнительно показаны доплата и итог мотивации; в RDL они вынесены в
общий блок справа. Коэффициенты/отгрузки/выполнение периода скрываются одним
переключателем. Узлы создаются в браузере по мере раскрытия. SQL группирует
данные до передачи в Python; действует общий предел 50 000 сгруппированных строк.

Локально проверяются формулы, годовое выполнение, валюты, веса коэффициентов, фильтры,
параметризация, иерархия и браузерные взаимодействия. Запрос не запускался на
живом DataWH; сверку с SSRS проводят на одинаковых данных и фильтрах.

Строка «% выполнения подразделений» перед «Итого» соответствует Tablix6/DataSet2:
фильтруется подразделениями и типом работника, без ограничения выбранными
авторами или товарной матрицей. Дополнительный фильтр года применяется и к ней.
План/факт этого блока не делятся. Множественные списки нового отчёта остаются
нативными, чтобы общая оболочка одиночных выпадающих списков не сбрасывала
множественный выбор. Для выбора нескольких значений используется Ctrl.


Исправление годового выполнения: в блоке «Итого» планы, факты, O0–O4 и средние
коэффициенты используют строки «Год», отдельно от сумм мотивации всех периодов.
Это действует на каждом уровне дерева и в общем итоге. Если хотя бы у одной
товарной классификации/сотрудника/подразделения/года нет годовых строк, годовые
показатели соответствующего итога показываются прочерком. Квартальные суммы
вместо отсутствующего года не подставляются; мотивация и доплата сохраняются.
Проверен пример с квартальным выполнением 95% и годовым 79%: «Итого» показывает
79%, при этом складывает выплаты квартала и года и добавляет доплату.

Выполнение подразделений включено в основную таблицу вместо отдельного блока.
Проценты совпадают по позиции с колонками выполнения соответствующего периода;
при включении подробных показателей также виден процент выполнения периода.
Для нескольких подразделений вычисляется отношение сумм факта и плана, а не
среднее процентов. Итог использует только годовые строки с проверкой полноты.
При сопоставлении периодов учитывается год: выполнение другого года не попадает
в квартальный столбец. Источник и независимость от авторских фильтров сохранены.

Расширенная таблица находится в раскрываемой панели «Расширенная таблица
мотивации». Нажатие на карточку текущей валюты открывает панель без запроса;
на другую валюту — формирует тот же отчёт с сохранёнными фильтрами и открытой
панелью. Заголовок панели также работает с мышью и клавиатурой. Карточки содержат
подсказку открытия; строка выполнения подразделений остаётся перед итогом внутри
таблицы. Для JS и CSS панели изменена версия адреса, чтобы обновить кэш браузера.

Над раскрываемой таблицей добавлена постоянная сводка «Итого по мотивации»:
строки USD/RUB и столбцы 1–4 кв., Год, Остаток, Итого. Периоды содержат суммы
с учётом выполнения, остаток — сумму доплаты за кварталы, итог совпадает с
карточкой соответствующей валюты. Отсутствующий период показан прочерком,
а настоящий ноль остаётся нулём. При нескольких годах столбцы получают год;
нестандартный период не теряется и выводится отдельно. Заголовки нативных
отчётов используют светлый фиолетовый фон и акцент в гамме портала.
