# Ревью sp_CalcBySub

Исходник предоставлен пользователем 09.10.2026. `sp_CalcBySub.original.sql` — неизменённый исходник; `sp_CalcBySub.refactored.sql` — кандидат для проверки на копии DataWH. Портал не устанавливает и не вызывает новый файл автоматически. Выполнения в SQL Server и измерения времени здесь не было.

## Исправления в кандидате

- Параметры `@Year` и `@PlanVersion`. Значения по умолчанию 2024 и «План продаж [Q1_2024] v4» соответствуют именно использовавшемуся итоговому отчёту, а не текущему году. План ограничен тем же календарным годом, что факт.
- Удалены расчёты #plan_2025 и #plan_2026: ни один из них не читался далее. Это убирает четыре ветви запросов к планам, их соединения и группировки. Количество проходов исходного факта пока сохранено.
- Два фильтра `YEAR(ClosedDealDate)=2024` заменены диапазоном `[DateFrom, DateTo)`, чтобы SQL Server мог использовать индекс по дате.
- В Q1 `СуммаПланUSD` и `СуммаПланUSDКварталValue` теперь берутся из плана, а не из факта (исходник строки 1250, 1260).
- В продажах значения K0–K4 при отсутствии настроек приведены к той же формуле, что Coeff_: `0.008*(1-0.71)`. Раньше выводились 0.0032, а выплата считалась по 0.00232 (строки 274–278). Правило минимальных коэффициентов из портала здесь пока не реализовано: процедура использует собственные исторические defaults.
- В окна уровня подразделения и KeyPlan добавлен год: расчёты разных лет больше не складываются в этих местах.
- Деление при расчёте скидки и доли плана защищено NULLIF. Деление Discount переведено на /100.0 для защиты от целочисленного типа. При неизвестном курсе исходная формула по-прежнему может дать NULL: нужна проверка валютных данных.
- Перед UPDATE Sales проверяются неоднозначные пары DocumentKey/Номенклатура; вместо случайного выбора строки расчёт завершается ошибкой. Добавлен индекс временной таблицы для этого соединения.
- Последний INSERT годовых остатков читает только квартальные строки, не ранее добавленные строки «Год».
- Удалены отладочные result sets TOP 10.
- NOCOUNT, XACT_ABORT, TRY/CATCH, откат всех изменений и блокировка повторного одновременного запуска этой процедуры. Читатели READ UNCOMMITTED/NOLOCK по-прежнему не получают гарантии согласованности.

## Следующая оптимизация после проверки эквивалентности

1. Один раз материализовать обогащённый факт и расширить его через CROSS JOIN `(VALUES (N'Политики'), (N'Продажи'))`: вместо двух сканов Sales/Product/Customer/Segments.
2. Аналогично материализовать выбранный план один раз для обеих ветвей коэффициентов.
3. Вместо повторяющихся CASE и окон каждого квартала построить таблицу периодов (Q1:1, Q2:1–2, Q3:1–3, Q4:1–4, год:1–4), нормализовать ключи VariationCalculate, агрегировать факт/план один раз на нужном уровне. Это отдельное изменение расчётной структуры с обязательным сравнением выплат.
4. Скалярные makeDocumentKeyDate/getCurrancyRateUSD проверить в фактическом плане: inlining зависит от версии SQL Server, compatibility level и определения функции. Рассчитать курсы по уникальным (DateInvoice,CurrencyCode), затем JOIN; не обещать ускорение без плана.
5. Кандидаты индексов: Sales(ClosedDealDate) с ключами соединений в INCLUDE; PlanSales(Version_,Date_,GoodsKey,Subdivision) INCLUDE(AmountUSD); уникальные/покрывающие ключи Goods(PlanningKey), Product(ProductCode), Subdivisions(SubdivisionKey), Customer(CustomerKey). Сначала проверить существующие индексы, типы/длины ключей, объём и статистику. Обычный индекс не исправляет leading-wildcard LIKE.

## Проверка на SQL Server

- Только отдельная тестовая копия DataWH: процедура изменяет Sales и пересоздаёт три постоянные таблицы. В облаке ничего в корпоративной БД не выполнялось.
- Получить фактический execution plan, включить `SET STATISTICS IO, TIME ON`, сохранить исходные результаты и время.
- Установить кандидат на тестовой копии, выполнить:

```sql
EXEC motivation.sp_CalcBySub
    @Year = 2024,
    @PlanVersion = N'План продаж [Q1_2024] v4';
```

- Сравнить количество строк и суммы плана/факта/мотивации USD/RUR по году, подразделению, автору, типу, группе, марке и периоду. EXCEPT в обе стороны дополнить сравнением COUNT_BIG по всем колонкам: EXCEPT не учитывает кратность дублей.
- Ожидаемые изменения: Q1 плановые суммы, диагностические K продаж, выбор года/версии и исключение годовых строк из расчёта остатков. Остальные расхождения исследовать.
- Обязательные случаи: скидка 100%, нулевая базовая цена, нулевой/отрицательный план, возврат, отсутствующий курс, отсутствующие коэффициенты, перекрывающиеся версии, несколько TypeDiscount, дубли DocumentKey, годовая граница, два одновременных запуска и принудительная ошибка после изменения Sales.
- Проверить права чтения, зависимые отчёты и восстановление схемы/индексов: DROP/SELECT INTO сохранён в кандидате и требует отдельного решения до промышленной установки.
